# 墓穴钥匙、锁门与媒体

本候选依赖 #74 的钥匙时钟，仍未开放正式墓穴地图。新增独立 ENCKMP01 format1／capability1，把相同六个稳定对象身份、三个图像配置、九个矩形、六个本地声音节点与两个 PCM 音源绑定到同一份不可变时钟资源。候选元数据 6628 字节；三个实际 tex3ds 输出共 167999 字节，两个实际解码 PCM 共 22828 字节。以上候选保存在 build 下，没有添加正式 RomFS、目录角色或保存编码。

来源固定为 `7d9246600fffe518408f5830d4848635019005a3`。独立配方记录原场景、脚本、纹理及导入设置、音频及导入设置、Master 总线和许可来源。图像按原帧无缩放重排，真实 tex3ds 转换器指纹在凭据中；运行时检查实际纹理字节数及 CRC，SHA 用于来源与离线转换凭据，不声称运行时做 SHA 校验。纹理、坐标、尺寸、层次、碰撞过滤、音源身份和音量均来自资源；共享核心没有游戏内容常量表。

`DungeonKeyMediaData` 根据现有时钟生成绘制请求和碰撞矩形。钥匙或祖先隐藏不自动禁用碰撞；拾取的延迟碰撞关闭由原方法状态驱动。门体与交互区域分别处理：门打开后解除门体阻挡，交互区域继续存在，已打开门的方法自行忽略重复交互。绘制保留父 TileMap、原节点顺序、帧矩形、居中、翻转和深度信息。正式渲染、物理投递与 UI 子树仍需单独接入。

`DungeonKeyAudioRouter` 仅把时钟的音频写入转换为声音请求，原方法的拾取通知不额外播放一次。三个钥匙和三个锁头保持独立声音节点。实际完成时，钥匙执行资源声明的原完成回调；没有脚本监听器的锁头仅清除原生音频占用，不合成删除或动画完成事件。场景代次、对象／资源归属、未知类型、容量、损坏与过期回调均拒绝；失败不发布部分加载或声音批次。未来平台服务仍须在提交前预留声音批次，并检查平台声音代次。

实际验证：

- 官方 Godot 3.6.2 两次独立运行，每次 69 个 Sprite 帧矩形、9 个原生矩形形状、6 个声音节点属性及 Lock 转向默认值完全一致，并与来源提取逐项吻合。未运行完整墓穴、接触求解或声音播放；没有像素、听感或真机一致性声明。
- 18636 项直接 GCC 9.4 ASan+UBSan 检查通过，启用正常泄漏检查，编译和执行输入前后不变。覆盖原生矩形对应的动态绘制、钥匙拾取、隐藏与延迟碰撞、锁头声音完成、门体打开与交互区域保留、实际两段 PCM 的独立读取／结束／重启、三张真实 T3X 字节、全部截断及原子拒绝。
- 8 项 Python 来源、重复原引擎、编解码和负向检查通过。Windows 仅配置与发现得到 307 项 CTest 和 1391 项 Python（1008 汇总＋383 专用），不是 Windows 运行通过。便携夹具重新解码真实音源并核对保留的真实纹理元数据，不伪造 GPU 文件。
- 新提交完整 GCC／Clang、真实 3DSX／CIA 仍待验收，尚无这批新媒体的模拟器或真机验证。

原始记录在 `reports/dungeon-key-media`。早期导入在缓存尚未建立时读取上游音频 remap 而报错；对照程序改为先建立资源缓存，再恢复原导入设置并逐项核对，所有诊断仍会阻断。随后三次证明收集器分别误用 Godot 文档头／Section 字段，均发生在原生观察完成后的记录阶段，失败记录保留。第一轮正负向测试把有符号深度值 `0xffffffff`（合法的 −1）误列为非法值；已改为真正越界的 4097，没有收紧合法数据或改原观察结果。

后续仍需生产声音／纹理准备与退役、正式地图和 UI、接触投递、存档及 Pippi 救援。不得根据本组件结果扩大游戏可玩范围。
