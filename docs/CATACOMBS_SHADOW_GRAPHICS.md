# 原版角色阴影时钟与图形服务候选

固定游戏上游为 `7d9246600fffe518408f5830d4848635019005a3`，原引擎为 Godot 3.6.2 的 `3cd3caab6779a7f3ec3bbeb9f200db50c735cfc8`。本候选补齐已声明阴影模式的时间推进、原图资源与生产绘制服务。完整墓穴、角色注册与接触分派仍未接线，不能据此声称墓穴已经可玩或新阴影已经在模拟器显示。

## 原版行为与数据

原 Player 的 `Shadow` 是完整原场景实例，子节点位置为 `(0,7)`，默认居中、可见、播放、无翻转，调制色为白色。三个模式的速度、帧数、顺序、循环和前后层次来自已审查的脚步声资源。七个原帧使用未裁边原图，水波的来源横坐标顺序是 `0,30,15`。新图集为 68×14，不缩放、不绘制替代素材，也不复制开发环境字体或导入缓存。

原项目启用 GPU pixel snap。原 `AnimatedSprite` 在叠加父变换之前向下取整局部偏移，所以普通阴影的局部绘制原点为 `(-8,4)`，magic 为 `(-9,3)`。共享核心保留这个次序；不将它等同于完整原 GPU 着色器、照明或最终像素一致。

`FieldStepShadowState` 按原引擎普通游戏路径，以 binary32 的 remaining／timeout 推进正向动画。切换模式、改变帧会重置时钟；重复同一模式或同一帧保持相位。隐藏、玩家自己的暂停布尔值、禁用绘制循环均不停止该子节点时钟；场景树的处理许可才控制推进。调用者传入实际处理许可与有界时间增量，不从屏幕是否绘制推断时间。编辑器 `UPDATE_VITAL_ONLY`、反向播放、变速与完整 Player 不在本候选范围。

`ENCSHDW1` 使用独立 format1／capability1，564 字节候选描述一个稳定来源配置、三个模式及七个帧；真正转换的 T3X 为 8,213 字节。128 字节头后的四段步长为 1／64／32／32，保存字符串、纹理身份与局部几何、模式和帧。来源 pin、版本、CRC、目录、拥有的字符串／连续帧跨度、保留位、有限数值、有限可执行帧时长、相对路径和纹理长度／CRC全部检查；失败保留原已加载对象。配置来源 ID 为 Player 场景节点路径的受检身份，不改变游戏存档格式。

## 生产服务的边界

`ShadowGraphicsData` 必须与同一组脚步声 Shadow 模式、初始策略及播放状态匹配。组合时检查配置／模式／帧、身体与镜头坐标，保留失败原子性。所有原图、绑定、速度和几何均在独立资源中，C++ 只执行模式与检查加载。

`ShadowRenderer` 在准备阶段校验文件长度／CRC，再从同一份字节导入纹理；拒绝数量、尺寸、旋转及 UV 布局不符的资源。之后按场景代次、帧代次、身体、状态所有权、可见性及前／后层次提交；过期、重复提交或未知阶段拒绝。绘制不做文件读取，退役和析构要求 GPU 空闲边界。身体注册、角色绘制顺序与场景拥有的脚步声数据生命周期仍由以后完整消费者负责。

真实 SDK 编译单元包含生产服务的全部方法，避免只在替身接口下编译。当前 `FieldScene::bind_steps` 对多边形 capability2 的拒绝继续保留，直到匹配的接触、完整角色与阴影服务共同接线。正式 RomFS、资源目录、存档和旧矩形资源未变。
