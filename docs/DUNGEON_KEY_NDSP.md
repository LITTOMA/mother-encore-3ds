# 墓穴钥匙与锁头生产声音队列

本候选依赖 #75 的独立媒体资源，补充生产 `AudioPlayer`、共享声道池与 NDSP 队列服务。它尚未由正式墓穴创建，不能据此声明新增可玩内容。没有改变资源格式、RomFS、稳定身份或存档。

准备阶段验证实际两段 PCM 的尺寸与 CRC，缓存共 22828 字节，并为六个原版声音节点保留独立游标；同音源共享只读缓存。激活要求可用的 NDSP 输出与一致的总线，缺少输出明确失败，不用猜测时长合成完成事件。平台资源和缓存成本不构成整机内存验收。

声音批次先验证场景、节点及声道所有权，预留全部声道，之后由调用者提交游戏状态，再提交播放。准备失败或取消不改变播放队列；播放提交与正常补充缓冲不读取文件或分配内存。重播从音源起点重新开始，停止不冒充自然结束。声音使用独立占有标签共享现有物理声道池，保留 BGM 等固定声道。

实际播放结束后，服务保存场景、节点和单次播放代次，等待游戏状态事务。`reserve_completed` 在副本上运行媒体资源声明的完成回调；调用者预留其他消费者并发布状态后才确认完成。取消保留待处理结束事件，方便重试。重播或停止仅使对应节点的旧结束事件失效；没有脚本监听器的锁头只更新音频占用。退出场景清理本地声音及回调，旧场景／旧播放／旧输出配置均不能回写当前游戏。

457 项直接 GCC 9.4 ASan+UBSan 检查通过，保留正常泄漏检查，实际退出码 0，编译及执行输入指纹前后相同。测试使用生产 `AudioPlayer` 与本服务、真实两段 PCM，以及明确的主机 NDSP 替身；覆盖六节点并行、共享缓存与独立缓冲、结束事务失败回滚／取消、旧播放代次、重播／停止／退出、声道不足、损坏数据、分配／缓存刷新失败和输出配置失效。准备后删除测试音源副本仍能播放；BGM 身份、代次和实际测试队列不变。测试复制的音源在结束时清理，证据保留在 `reports/dungeon-key-ndsp`。

Windows 仅完成配置与发现，得到 308 项 CTest；不是 Windows 运行通过。生产头另由真实 ARM 编译单元纳入 CTR 构建，避免仅在主机替身头下检查，但新提交的真实交叉构建与完整 GCC／Clang 回归仍待执行结果。没有声音听感、模拟器新地图或真机验收声明。
