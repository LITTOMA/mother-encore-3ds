# 标题与加载

## 实现

标题 logo / 菜单在 400×240 上屏按外部偏移 (+40,+30) 居中；原 320×180 背景保持 1:1，按下缘居中 (+40,+60)，扩展处填充受检的原图边色。参考模式数据与转场时序不变，圈形转场中心随视口偏移。

加载提示是 3DS 平台适配，使用原版 Ninten Walk Right 帧 20 → 21 → 22 → 21，每键 0.2 秒、循环 0.8 秒、31×29 像素。提示数据和紧凑贴图提前载入；正常游戏帧在加载结束后替换提示。原版受检 SceneTransition / cacheLoader 路径不提供这个专用加载提示，不能将它描述为上游行为。

提示位置按已完成任务计数推进，不代表剩余时间或字节进度，详见 [任务进度与区域采样](CANDIDATE_PROGRESS_REGION.md)。加载期间游戏物理、剧情和 RNG 不推进，结束后丢弃加载耗时产生的物理追赶累积。LOAD 先准备独立新 owner，成功后提交。

正常游戏画布清屏色读取受检的 project.godot 数据，当前为 RGB(28,28,28)。不替换素材内黑色、独立淡出遮罩或参考模式黑边。

音频后端先检查 NDSP，不可用时避免无意义地读取整套 PCM；可用音频仍完整校验。场景重置停止声音并复用已核验的流和缓冲。实际可听性仍未验收。

加载复用当前不可变房屋 UI 资源和战斗数据；CRC 使用等价表算法，Tex3DS 读取按至多 8,192 字节分块。主线程在真实进度边界绘制提示，不由后台线程操作 GPU，也不跳过 CRC、截断或 I/O 错误。标题与命名纹理的驻留互斥处理见 [纹理生命周期修复](NEW_GAME_TITLE_TEXTURE_FIX.md)。

## 测量范围与限制

一次 Azahar 2126.1.2 局部启动测量记录场景准备 10.124 秒、530 次提示绘制、最大间隔 725 毫秒；标题准备 384 毫秒、11 次绘制。该测量属于当时的特定构建与模拟器配置，不能作为当前源码、独占机器或真机性能结论。

分块可缩短提示停顿，但 SDK 导入和收尾仍有不可中断工作。提示绘制也增加总开销：相应局部测量中，不带最终提示的阶段版为 8.206 秒，带提示版为 10.124 秒。因此不能宣称所有冷启动更快，或以提示动画流畅代表游戏帧率。

当前完整加载、战斗背景和资源驻留的性能需按构建配置分别测量。核对准备时间、最大无更新间隔、首次可交互帧和内存峰值；缓存命中与冷启动分开比较。

## 验证要求

资源读取与提示应覆盖 CRC、正常 EOF、截断、真实 I/O 错误、动画时序、400×240 / 320×180 位置、UV、释放与 observer 隔离。验证复用路径仍完成校验，失败任务不会显示成功。

设备检查应走正常标题 → 命名 / LOAD → 世界流程，并记录精确源码、配置和产物。主机对照、ARM 编译和模拟器观察不能代替 Old / New 3DS、音频可听性与安装 CIA 验收。当前范围见 [STATUS](STATUS.md)，测试入口见 [TESTING](TESTING.md)。
