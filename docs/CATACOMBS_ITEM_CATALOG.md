# 墓穴物品目录与多来源领取候选

原墓穴七处掉落使用三种道具：四份Hamburger、一份Fries、两份Antidote。目录候选从已审查掉落来源和固定上游YAML／翻译／20×20图标导出，稳定定义号5／6／7追加在现有1–4之后。原HPrecover50／20与poisoned解除规则保留在来源数据中；普通Items投影仍保持动作禁用，不借现有只支持零效果的富文本投影启用消费。三份纹理由实际固定tex3ds生成，各4117字节，来源、工具指纹与许可记录独立保存，没有复制字体或第三方程序到发行内容。

现有会话资源v11每种新增道具只允许一个旗标，无法表达多处同种道具。新增独立资源能力／版本v12允许同一物品有多个不同来源旗标，每行仍只授予一次且剂量一致。背包和仓库的合计持有量不得超过已经置位的来源数量；仓库上限必须等于全部来源数量，拒绝重复旗标、不同剂量、超授予、错误合计和缺失策略。使用或丢弃后允许持有量减少，原一次性旗标保持不变。v1–v11读取保留；v11继续拒绝重复物品身份。真实游戏存档ENCSNAP1版本和编码不变。

随后已将七种正式道具、会话v12、START消费效果及仓库资源整合，生产二进制与独立扩展的冻结v11夹具一致；全部128种领取组合同时比较候选与生产会话的结论，见[道具资源整合](ITEM_ADMISSION.md)。原游戏存档编码保持不变。墓穴场景与普通拾取仍未接入，不能把资源及核心校验通过当作已经可以从正式棺材取得这些物品。

实际验证：GCC ASan／UBSan及正常泄漏检查中，新多来源校验26525项通过，覆盖全部128种领取旗标组合、背包／仓库分配和280次沿用原游戏存档的往返；既有NativeSession 20808项同时通过。只重新编译一个核心模块和两个测试程序；基线117模块归档的251项输入已逐项核对，唯一变化是被替换模块及仅注释变化的头文件，新对象覆盖归档中的旧对象。这不是完整主机重建。22项相关Python检查通过，覆盖来源／目录／纹理损坏、身份、类型、重复JSON字段、夹具幂等性和v12旧载荷保持。CMake实际仅完成Windows配置及377项发现，两项新检查通过fixture依赖登记，没有运行完整CTest。

原始日志、精确源码、夹具清单和限制见 `reports/catacombs-item-catalog`。首次候选把富文本投影与HP数据混用，被原Items校验器明确拒绝；修正为保持动作投影禁用，错误日志保留。首次本地CMake配置因沙箱无法读取只读SDK注册信息失败，允许读取后配置通过，两个记录均保留。完整GCC／Clang矩阵、本分支真实3DSX／CIA、新模拟器及真机仍未验收。
