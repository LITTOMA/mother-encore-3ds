# 墓穴棺材与木桶

新增固定原作 `7d9246600fffe518408f5830d4848635019005a3` 的破坏物消费者候选，包含实际场景中的16个棺材、49个木桶及16个内容目标。正式墓穴尚未接入，这项工作没有扩大当前游戏可玩范围。

`content/catacombs-breakables.json` 固定50份实际来源及受审方法。转换器从继承场景、实例覆盖和脚本读取动画、碰撞矩形、父节点、掉落目标、金币数、旗标与调参，编译独立的12,008字节 `ENCBRK01` v1 / capability1。两个家族内嵌原有 `ENCPCL01`，没有修改其格式、目录capability、规则兼容或游戏存档；原对象旗标键仍使用原作字符串。候选资源只在开发夹具中生成，不伪装成已接入正式场景的发布资源。

## 已实现的源行为

- Ready按appear/disappear旗标决定可见性和删除；隐藏掉落保留原物件定位。受击先按需要暂停玩家，再等待原距离延迟，即使距离为零也经过SceneTreeTimer。
- 延迟结束后发出震动请求，播放原Break动画，清除指定碰撞位并关闭身体形状。内容路径在此时重新解析，已移走的内容不会凭旧路径被再次掉落。
- 掉落保留原start_pos/changingParents可选属性、捕获的形状句柄、父节点与位置，使用原Timer恢复碰撞。进入Objects的内容先上抬，再回弹；物理处理在回弹**开始**时恢复，不能推迟到回弹结束。
- 只有实际带CoinSpawner且原旗标未设置的分支写入破坏旗标并请求金币。棺材不因此凭空获得持久“已破坏”状态。动画完成后按原New_parent重新挂接，保留局部位置和身份。
- 声音按源动画的播放请求记录：棺材明确播放、停止；木桶仅播放，让音效自然结束。使用既有音效身份与源媒体，不新增素材副本。

SceneTreeTimer使用binary32剩余时间，节点Timer使用double剩余时间；补间时钟及位置运算保留原binary32语义。cubic-out / bounce-out数学子集来自固定Godot 3.6.2，保留Godot和Robert Penner的MIT声明。地图位置、时间、偏移、碰撞位和金币数量均来自二进制资源，没有C++游戏内容表。

消费者在准备阶段检查父节点、内容快照、形状、金币和声音服务；场景代次绑定到每个请求。失败时不提交部分状态。成功提交保留原内容、形状和已有旗标节点，只更新变化字段；未触发及已结束的物件每帧不复制或分配。请求接收者仍须在正式场景的事务中完成预检和执行。
