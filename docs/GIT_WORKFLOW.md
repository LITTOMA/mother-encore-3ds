# Git 工作流

日常开发使用标准 Git 主题分支与 Pull Request。以当前 `main` 为基础，每个分支聚焦一项可审查的改动；未完成的工作使用草稿 PR。

## 分支与提交

- 使用能说明目的的分支名称，例如 `fix/title-texture-loading` 或 `feature/scene-resource-loader`。
- 提交说明描述具体问题和结果。工作流 / 构建修复应注明实际失败与验证层次。
- 将完成的提交推送到对应远端分支，核对远端提交一致。日常开发保留已发布历史。
- 不混入无关实验、构建输出或个人环境配置；依赖未合并分支时在 PR 中注明。

## PR 与检查

PR 描述包括改动目的、上游来源、受影响范围、兼容性及实际验证。使用准确的命令和结果，明确失败或未运行的检查。来源指纹改变必须对应语义审查、实现映射和相关测试，不能只更新 SHA 或 trace 期望使检查通过。

日常提交和 PR 状态变化不自动启动测试。合入 main 后自动构建真实 3DSX / CIA 并上传 Actions artifact；构建或打包失败时不上传不完整产物。全面验证仅由明确手动请求触发；审查时区分当前提交已验证、未运行和失败的状态，并检查相关来源、许可与行为。主机、sanitizer、交叉构建、打包、模拟器和真机是不同层次；一个层次通过不代替其他层次。CI YAML 存在不代表 CI 已运行。

## 上游与资源

官方上游只通过固定 `.gitmodules` 与 gitlink 引入，`upstream.lock` 和全量 inventory 应一致。子模块只读，更新候选在独立 checkout 审查，步骤见 [UPSTREAM_WORKFLOW](UPSTREAM_WORKFLOW.md)。

生成资源通过受检工具更新，不手改 pack / manifest 或移除未知内容以通过检查。真实游戏内容、绑定与调参保持程序 / 数据分离。26 项上游衍生 PCM 由既有工具恢复，不重复纳入 Git。

SDK、第三方工具二进制、`build/` / `dist/`、凭据、个人存档和运行缓存不入库。新增素材与依赖需记录来源、指纹和对应许可；源代码与资源的许可证不能混为一体。

贡献指南见 [CONTRIBUTING](../CONTRIBUTING.md)。
