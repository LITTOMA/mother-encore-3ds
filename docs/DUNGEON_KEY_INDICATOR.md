# 钥匙计数提示状态候选

本候选实现固定上游 `7d9246600fffe518408f5830d4848635019005a3` 的 `KeyNumber.gd` 三个方法，以及 uiManager 的提示更新／关闭分派。新增独立 `ENCKUI01` format1／capability1，749字节，嵌入原钥匙策略的稳定身份；保存初始位置、文本、显示状态、滑动／弹跳参数、两种曲线及已审查诊断能力。C++只有加载、执行与生命周期，不含真实内容常量表。

状态包括滑入、滑出、弹跳序列、关闭途中重新打开及被取消的关闭等待。数量为零时关闭，不把旧标签改写为零；初始标签仍是来源中的 `x 4`，位于原坐标的屏幕外。当前使用原作坐标，400×240布局另行准备。计数由外部受检调用方提供，尚未接入正式全局计数、存档、图标、字体、完整UI或墓穴场景。

原脚本有明确错误路径：在已启动的弹跳中再次更新，或零时长启动后更新，会向已启动的 SceneTreeTween 追加步骤。原引擎先报告追加失败，再报告空对象调用 `from`；标签已经更新，原队列没有新增步骤，外层 `open` 继续其原逻辑。本实现仅将这组已逐项复现的错误表示为受检诊断，不生成成功的排队事件；未声明该诊断的资源遇到它会拒绝并保留此前状态。未知能力、版本、曲线或错误仍拒绝。

计时按实际 Godot 3.6.2 的 float32 入参、时长、累计及余时顺序执行。资源保留脚本参数的双精度表示，在执行API边界转换；正时长还须能表示为正常float32数。零时长推进会启动队列，但不写入属性。新建滑入／滑出队列保留原引擎默认线性曲线，水平属性单独使用Sine／Out；由 `update` 新建的队列默认Sine／Out。尚未开始的后续属性继承各自队列的曲线，不能全部强设为同一种曲线。具体引擎机制已核对[对应提交的实现](https://github.com/godotengine/godot/blob/3cd3caab6779a7f3ec3bbeb9f200db50c735cfc8/scene/animation/scene_tree_tween.cpp)和[头文件](https://github.com/godotengine/godot/blob/3cd3caab6779a7f3ec3bbeb9f200db50c735cfc8/scene/animation/scene_tree_tween.h)，原MIT许可头、来源凭据及指纹保留在 `reports/dungeon-key-indicator/engine`。这只映射当前HUD所需的序列机制。

实际验证在 `reports/dungeon-key-indicator`：

- 原脚本逐字复制，官方引擎两次独立运行14／15，各八组、91个状态完全一致；三处具体触发各对应一组已知原版错误，受检退出17。原生HBox／Label与Tween参与执行；区域／数量存储是明确服务，不观察图标、字体或最小尺寸布局。
- 新鲜直接编译的GCC9.4 ASan+UBSan正常泄漏检查2521项通过，输入前后指纹不变。覆盖91个原观察、曲线继承、余时边界、文本与数量、关闭取消、零时长、原诊断及未声明诊断的原子拒绝、队列／诊断容量、全部截断、未知格式／能力、嵌套身份、浮点与文字损坏，以及代次退役。
- 八项Python来源、编解码、重复夹具与负向检查通过。Windows只完成配置／发现：314项CTest、1405项Python（1022汇总＋383专用），不是Windows运行通过。独立编译CLI与夹具生成相同字节，越出build的输出路径拒绝且未写文件。
- 早期对照适配器的字段访问、独立脚本模式未加载autoload、缩进和诊断文字断言错误均保留。新增零时长用例确认三处同类原错误；最终新增继承曲线用例得到91状态。第一轮核心以双精度累计并先裁减输入，误把多段弹跳结束边界当作已停止；已按受检引擎源码修正执行顺序，原观察没有改写。中间2508项和最终新增负向后的2521项结果分别保留。
- 校验所有权标记、每个文件指纹、工作区边界、无重解析点及无运行中的原引擎后，清理14个独立对照项目和两个被替代测试程序，共8752225字节；保留外层日志、输入、来源与最新测试程序。

完整新提交的GCC／Clang、消毒器与真实3DSX／CIA等待验收；本候选不扩大正式可玩范围。正式UI显示、计数和存档接线、墓穴模拟器及真机仍未验证。
