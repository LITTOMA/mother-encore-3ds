# Catacombs 五个音乐区域

本组件为固定上游墓穴五个 MusicChanger 区域提供来源审查、原矩形几何、音量／旗标／淡入淡出绑定及两首原曲候选。复用现有 ENCMUS01 v1、ENCZON01 v1、ENCAUD01 与共享音乐核心，没有新增运行格式或游戏内容常量。正式墓穴、全局声库路由、存档与 NDSP 仍待接入，当前可玩范围不变。

## 来源与资源

content/catacombs-music.json 核对固定上游 7d9246600fffe518408f5830d4848635019005a3 的十二份来源：墓穴、原 MusicChanger／音频管理／旗标方法、玩家、项目与总线、两首曲目及各自导入配置、原许可。仅解析声明范围，不为其余地图节点设置通用忽略规则。完整地图根脚本、角色、战斗和剧情仍待分别实现。

MusicArea 与 MusicArea6 使用 Underground.ogg，要求 hidden_entrance_opened，音量为 0／-10dB；MusicArea2／3／4 使用 A_Ghastly_Site.mp3，在该旗标未开启时有效，音量为 -5／-10／-15dB。两首原导入都循环，循环起点分别为 3.77／16.694秒。五个区域沿用 1秒淡入、1.5秒淡出与源矩形；隐藏 Music 父节点没有禁用 Area2D。

真实 FFmpeg 生成两份 44.1kHz 双声道 PCM，共28,279,900字节，记录源指纹、CRC、帧数、循环起点与转换器指纹。850字节区域绑定、323字节几何、401字节声库元数据均通过既有编解码器生成。测试只从原转换记录重建这三份小资源，并验证与实际转换结果逐字相同；大 PCM 留在私有候选目录，不进入 Git、测试夹具或正式 RomFS。

## 原引擎与共享核心

两次 Godot3.6.2 冷启动（native2／3）载入五个原样区域节点、原 MusicChanger 场景及四份原矩形资源，在隔离根节点下检查全部属性与全局顶点。该阶段的单例是明确服务，没有执行完整根脚本或玩家物理。

另以原 MusicChanger 回调和已审查的音频管理／旗标方法运行十组回调序列，每次92个状态观察，包括同曲复用、不同音量、入口旗标、UI／战斗门控、离开、门口停止及退役。两个场景槽都重新实例化相同五个墓穴区域；序列名称保留原测试家族名，不意味着执行完整 Podunk／Mayor 场景。原有 Podunk／Mayor 轨迹未改，单独回归。

观察器使用显式玩家／UI／旗标服务、手动区域回调、冻结 Tween 和完成事件。原导入的 loop／offset 明确设入实际缓存资源；没有把编辑器自动生成的默认 .import 文件说成与原导入器等价。原始生成导入记录也已保留。两次 reference.json、geometry.json、scenes.tsv 逐字一致；新语义审查在 compatibility/reviews/catacombs-music-v0410.json。

GCC9.4 ASan+UBSan 正常泄漏检查通过3,090项墓穴检查，包含原几何／旗标／音量、实际转换音频元数据及循环游标。旧音乐轨迹与负向检查5,454项也通过。使用地形任务新编译的116源共享核心库，逐项确认全部运行源和公共头文件输入未变；不声称本任务再次编译了全部源。比较器提取到公共测试辅助头，原比较函数、旧负向函数及旧主函数的字节保持不变，旧期望未改。

11项 Python 来源／版本／覆盖／重复字段／损坏结果／输出路径检查通过。Windows仅配置与收集324 CTest、1,440 Python方法（1,057聚合＋383专项），不能算执行。完整当前 GCC／Clang、真实3DSX／CIA、正式场景、NDSP、模拟器与真机尚待完成；不作听感或硬件通过声明。

## 证据与清理

证据位于 reports/catacombs-music/。初版误用 Section.path、私有写入器在引擎启动前失败，以及 native1 的未使用服务参数诊断均保留；修正接口和参数，没有屏蔽警告。清理审计初次误把生成项目／导入记录当作原样来源，已在删除前拒绝；随后区分冻结生成文件与实际复制的原源码／音频，逐一核验来源、标记、精确路径、进程及重解析点。

五个临时原引擎工程和重复转换目录已清理，释放42,153,517字节。实际候选 PCM、小资源、测试程序与日志保留。正式场景接线后仍须使用真实构建和模拟器验证 BGM。
