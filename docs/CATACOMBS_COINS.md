# 原版金币、生成器与圆形移动

本候选实现固定原版 `7d9246600fffe518408f5830d4848635019005a3` 的 Coin、Sparkles、CoinSpawner 和 AbstractSpawner 所需共享核心。它是完整墓穴的一个依赖，当前没有扩大正式可玩范围。自动接触采样、具体场景实例绑定、生产金币画面／现金 HUD／PCM 输出和完整墓穴仍未接线；没有硬件验收。

## 来源与独立资源

`content/catacombs-coins.json` 审查19份原文件及所选方法，`tools/coins.py` 核对原文件、完整节点／属性、动画轨道、工厂父节点和方法指纹。游戏数值、绑定、动画、材质和纹理区域均编译进独立二进制资源；C++只执行已加载的结构。

尚未发布的 `ENCCOIN1` v1、capability 1 使用九节：

| 节 | 记录字节 | 内容 |
| --- | ---: | --- |
| policy | 112 | 九个 binary64 规则值、十个 binary32 形状／时钟／显示值 |
| metadata | 96 | 角色、层／掩码、帧数、动画 ID、音源和来源引用 |
| clips | 24 | 动画稳定 ID、长度、循环、连续 key 范围 |
| keys | 24 | 目标、时间、binary64 值、更新模式 |
| directions | 8 | 原引擎产生的360个方向向量 |
| atlas | 24 | Sparkles 的40帧、纹理引用和区域 |
| material | 48 | 原颜色与初始着色器值 |
| assets | 24 | 五个原资源引用与实际工厂父节点 `Objects` |
| strings | 1 | 完整拥有且无重复的字符串池 |

当前编译资源4,950字节，只生成到 `build/` 测试资源。没有新增游戏存档、旧资源格式或正式场景 capability。SHA、CRC、目录、跨度、版本、保留位、数值和字符串所有权均受检；失败加载保留现有合法数据。禁止未知目标、形状或来源悄悄通过。

原脚本使用 `Vector2.RIGHT.rotated(randi() % 360)`：这里是整数弧度，不能擅自改成角度。Sparkles 的 Ready 先使用共享随机流，接着才是速度、方向和跳跃高度。数据和测试保留实际结果。

## 执行顺序与结算

`CoinActor` 分开处理原 idle／physics 时钟、动画、Tween、落地取整、延后形状变更和删除。重复拾取不重复加钱；现金提交到实际 `SessionSnapshot.cash`，不重建角色存储。HUD、落地音和拾取音仍是待场景实际交付的请求，不代表已经听到生产音频。

`CoinFactory` 使用原生成器的计时方式：判断间隔后生成一个金币，再推进计时；重新调用保留计时进度。子节点 Ready 立即消耗同一随机流，原树中已存在的子节点先处理，因此新金币从下一个物理帧才移动。测试覆盖默认五枚、三枚后再两枚、生成中以一枚覆盖等情况。父节点、场景 epoch、拥有者、随机流和数据代次必须有效；分配身份不回退，不遗留待交付请求。原 Breakable 不主动移动 CoinSpawner，后续必须从原场景层级确定每个实际工厂位置。

`CircleMotionSolver` 仅支持已审查的静态平移矩形、凸多边形和凹形线段。它保留矩形与凸形的原分离轴顺序，不扩张旧碰撞接口。Godot 3.6.2 原实现及许可已标注；`MIN_CONTACT_DEPTH_FACTOR` 的 double 常量再转 float 等精度路径按原源码保留。

## 已完成的验证

两次全新原引擎运行各产生1,573条金币状态、9条实际接触信号和33条生成器快照，原始结果相同，SHA256 为 `609bbb54e8f0d5b00b6f2bde8a8a06d35ccfe205f234ea8aa82cd5d2ec4b4923`。源 Coin／Sparkles／生成器及预制体未修改；玩家类型、现金显示和音频请求记录器是明确的测试提供者。核心重放实际接触输入，尚不代表自动碰撞接触已接线。

两次官方 Godot 圆形移动运行各44种输入、246状态，原始 SHA256 均为 `46a04836794688a482c10b1417fe469792ad01da627fe2b332c2f32eae6b2177`。40种单障碍输入保持精确结果。四种双墙角落存在保留的瞬态浮点差异，使用原碰撞 skin 和相同落地取整核对；原 Coin 不使用返回速度。金币紧角落用例只对瞬态位置采用同一语义界限，其他状态、结算、随机数及事件时机继续精确比较。原记录没有重写。

本地普通泄漏检查的 ASan／UBSan 实际通过5,407项资源检查、71,367项金币检查、6,094项工厂与子节点检查，以及3,788项圆形移动检查。前三项编译新模块并链接已核对来源的旧核心归档，不称为完整核心重建。11项 Python 检查覆盖来源、解析、异常版本／字段／数值、冻结记录及防篡改缓存。

`compatibility/reviews/catacombs-coins-v0410.json` 固定来源、两个生产器、观察协议、测试转换器和四份真实运行；`tests/prepare_coins.py` 只在来源与原始结果全部匹配时产生测试资源。CMake 登记独立 fixture 和四项 C++ 检查，3DS 构建明确编译相同三个核心文件。完整 GCC／Clang、正常泄漏消毒器和真实 3DSX／CIA 仍待当前候选的正式运行，不把已有组件检查写成完整通过。

当前官方 Breakable 游戏的两次90检查点开局回归也不构成金币、完整墓穴或硬件验收。

组合的49项 Python 检查通过；Windows Release 配置实际发现362项 CTest（包括五项金币检查及四组汇总），这只是登记检查。最初未指定 MSVC 配置而发现零项的探针及修正原因保留在 `reports/coins/frozen-integration/`，不计作测试通过。
