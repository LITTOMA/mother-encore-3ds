# 墓穴掉落物与棺材交互

候选共享核心已连接原七个掉落物、`ItemHolder` 的库存分配与原棺材消费者；尚未接入正式墓穴场景，不能据此扩大可玩范围。固定来源仍为 `7d9246600fffe518408f5830d4848635019005a3`，审查记录见 `compatibility/reviews/catacombs-dropped-items-v0410.json`。

## 资源与执行

七个稳定实例、Hamburger／Fries／Antidote 的来源、剂量／类别、两份碰撞形状与实际子路径、两条显隐动画和31项数值／曲线选择均编译为独立 `ENCDRP01` v1／capability 1资源。当前大小为 1907 字节，C++只执行受检加载、库存和生命周期，不包含这些游戏内容表。包格式、执行能力、规则与游戏存档独立；存档格式与正式资源目录／Session可接受物品范围尚未扩张。

原七个棺材都把物品放回 `Objects`，先弹出再由玩家拾取；`Bottom2` 是棺材自身的目标父节点，`interact_content` 均为false。原脚本只暂时关闭物品的交互Area碰撞，保留StaticBody2D子节点碰撞。真实破坏物消费者现在发布一次 `ContentReentered` 事件，掉落物核对来源、归属、时钟及请求队列后消费；金币消费者保留这个已知的其他归属事件，未知类型仍拒绝。

同父节点的移除／重新加入也会让原Godot子Tween执行 `stop_all()`。其后的 `start()` 会立即 `seek(0)`，因此背包已满时，重新挂入过场景的物品会立即呈现回弹起始角度。实现依据固定引擎的 `tween.cpp`，并经过保留的原版组合记录验证；没有改动画目标、时长或期望记录来隐藏差异。重复或带未审查活动时钟的重新挂入会明确拒绝。

库存按实际队伍顺序寻找第一个未满成员，钥匙绕过普通背包容量。背包满时仍执行原Item构造、生成身份并设置独立预览；成功时只提交相应背包与旗标，保持无关存储。外部身份时钟返回后重新核对库存、随机流、身份账本、资源代次和提示控件。旧代码在控件被销毁或角色库存被外部替换时的内存错误已用消毒器实际复现，失败日志与原代码快照保留；新检查拒绝继续提交。
