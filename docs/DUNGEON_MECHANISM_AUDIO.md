# 机关音频归属与请求消费者

`ENCDMP01` 保持格式 1，新增独立能力 2：9192 字节包含已有几何／时钟、七个声音归属和四种音源的 `ENCAUD01` 元数据。能力 1 的 7356 字节几何仍可读取。声音节点与管理器选择器记录在独立审核资源中；C++ 不保存原节点名或资产编号。源音频审核配方升级到 schema 2，仅把三个精灵类别的节点选择器移到数据；实际包、四份 PCM 和音频库共六个文件逐字不变，正式 RomFS、规则和存档均未改变。

六个机关各自拥有原版 `AudioStreamPlayer`，操作受限提示属于全局 `audioManager` 的 `switch` 通道。加载器按稳定身份、路径、来源 SHA、循环、增益／音调与墙门时钟交叉核对，拒绝缺失归属、重复、未使用音源、未知能力、损坏及非有限值；失败不提交部分状态。PCM 保持独立文件，在准备时通过既有流检查大小和 CRC。

共享 `DungeonMechanismAudioRouter` 把已检查的机关事件映射为明确的声音命令。重复 `playing=true` 保留为独立请求，不能因节点已经播放而忽略。整个批次先验证场景 epoch、请求种类和真实归属，错误保留调用方原输出。离场只产生六个原节点的停止命令，不关闭全局提示通道；退役后的旧场景拒绝再发命令。音乐、镜头、UI 和计时请求继续交给各自消费者，未知事件明确报错。

依据实际读取的 [Godot 3.6.2 AudioStreamPlayer 实现](https://github.com/godotengine/godot/blob/3cd3caab6779a7f3ec3bbeb9f200db50c735cfc8/scene/audio/audio_stream_player.cpp) 及同提交头文件，`playing=true` 调用默认从零开始的 `play()`，音频线程另行处理待停止和 seek。这里只验证原请求及归属，不把请求次数说成实际可听的重播次数，也没有声称重现混音线程或波形。

实际验证：

- GCC 9.4 ASan+UBSan／漏检开启：18792 项加载、七归属／四份真实 PCM、独立流与重启／结束、请求映射／退役、全部截断和错误路径通过。
- 原版 232 个观察重复两次，联接实际声音请求与绘图的 67996 项检查通过，原版期望未改。
- 旧能力 1 的 15486 项几何检查及 66128 项时钟联测通过；本阶段 20 项 Python 来源、兼容及负向检查通过。
- Windows 仅配置／发现 299 项 CTest、1366 个 Python 方法；不是 Windows 原生全量执行或当前完整交叉验收。

证据见 `reports/dungeon-mechanism-audio-binding/source-consumer-1`。此前 1b72953 的完整 GCC 为 294/295，唯一汇总超时、未执行 GCC sanitizer；Clang 各 279 及真实构建通过。测试分组修复独立保留在 #72；当前版本仍待完整验收。
