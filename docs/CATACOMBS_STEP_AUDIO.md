# 墓穴脚步声媒体与播放

八种原版脚步声已通过受检转换器生成独立候选音频包，并补齐生产缓存播放服务。它们尚未接入正式墓穴；本页的主机与原引擎检查不能替代实际 NDSP 可听性、模拟器或真机验收。

## 来源与资源

来源固定为 `7d9246600fffe518408f5830d4848635019005a3` 的八个 Footsteps MP3、各自原始导入参数、`Player._set_running`、`AudioManager.add_sfx/play_sfx/get_sfx` 和原版总线。配方为 `content/catacombs-step-audio.json`，语义映射与两次原引擎凭据为 `compatibility/reviews/catacombs-step-audio-v0410.json`。

主音频包已有 60 项，上限为 64 项，因此没有将八项追加进主包或放宽其容量。新媒体沿用独立 `ENCAUD01` 格式，每项为 44.1 kHz、双声道、17,640 帧的完整循环，PCM 各 70,560 字节，合计 564,480 字节。循环起点保持为零；声音身份、路径和 SHA 来自既有脚步声资源，没有在 C++ 中加入游戏内容表。

候选仅在 `build/` 生成，不手改生产包或清单，不提交 PCM、导入缓存、工具或 DSP 固件。转换器原始输出凭据及实际文件绑定保留在 `reports/catacombs-step-audio/conversion/`。游戏素材继续适用上游许可与原有声明，仓库 MIT 不重新授权这些内容。

## 原引擎对照

官方 Godot 3.6.2 实际运行所选原样方法，加载原版八个音频与完整默认总线，保留一个名为 `run` 的真实 `AudioStreamPlayer`。每项记录初始、播放、重复请求、停止四个状态，共 32 项。两次完整文档一致，SHA-256 为 `dd244192c9d266858967ea7535fcf3b142bbf4b571740de1edbf3a170c877215`；原始结果、引擎日志、生成适配器和输入指纹在 `native-1/`、`native-2/`。

观察环境明确使用 Dummy 音频驱动、手动继承的 `run_sound` 与 MOVE 标志，没有运行整个 AudioManager 初始化、设置或完整移动脚本。检查覆盖原始总线名称／音量／静音、节点复用、SFX、音量 0、音高 1、非自动播放、完整循环和稳定播放状态。没有把 Godot 解码样本逐字等同于 FFmpeg，也没有声明精确停止延时或听感相同。

早期第二次观察假定停止后两个极短 idle 帧足够，实际三个停止状态仍显示播放。AudioServer 独立混音，观察器改为有上限的 10ms 定时采样，并要求三次连续稳定；没有修改游戏脚本或放宽状态期望。更早的导入缓存失败、原观察失败和第三次中间结果保留在 `preliminary/`。最终两次使用同一严格验证器与生成指纹，不用失败结果充当通过结果。

## 生产服务

`FieldRunBankAudioService` 借用持久 AudioPlayer 的输出配置与全局音量，拥有独立包副本、八份 LINEAR 缓存和一个池化声道。准备阶段校验来源绑定、长度和 CRC，按最多 2,048 帧读取并发出加载通知，允许平台在加载中持续补给已有 BGM。缓存再次核对 CRC 后才提交 DSP 缓存刷新；播放期间不打开或读取媒体文件。

服务按场景代次和单一命名所有者领取声道，要求旧 Run 声道先退役。全部源事件、声音索引、最终注册／播放状态在硬件变更前验证；重复同音播放不重启。循环缓冲按已审查帧游标分段，用户 SFX 音量只作用于本声道，Master 由持久播放器统一处理。退役、输出配置变化、未知波形状态、失配所有权或无空闲声道均明确拒绝或释放，不静默覆盖其他音频。

完整场景还必须负责所有者生命周期与新旧 Run 服务切换。本次没有移除旧 `FieldScene` 对多边形脚步声的拒绝，也没有把候选服务假定为已接入游戏。
