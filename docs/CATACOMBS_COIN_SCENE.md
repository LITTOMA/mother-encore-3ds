# 木桶与实际金币生成器的连接

本候选把墓穴65个 Breakable 中49个木桶的金币请求交给实际对应的原生成器，补上先前仅记录请求的边界。它包含独立绑定资源、具体实例拥有者和原版组合回归，当前仍未开放完整墓穴：TileMap 地形、其他 NPC／AI、自然挥棒与自动拾取接触、生产图像／现金 HUD／PCM 和完整场景遍历尚未接线，也没有硬件验收。

## 来源与身份

固定原版提交仍为 `7d9246600fffe518408f5830d4848635019005a3`。`content/catacombs-coin-scene.json` 核对原 Catacombs 场景、已有金币／破坏物 recipe 和49份稳定实例身份；`tools/coin_scene.py` 重新展开原1820节点图，检查无重复／遗漏的木桶到生成器对应关系。

原木桶下的 CoinSpawner 有 `(0,8)` 局部偏移，不能直接拿木桶坐标或挥棒位置生成金币。例如第一个木桶位于 `(-592,-272)`，其生成器实际位于 `(-592,-264)`。木桶播放完破坏动画后移到原 `Bottom2` 层；原 `Objects` 和 `Bottom2` 都是单位变换，因此生成器世界坐标保持不变。转换器检查所有祖先、目标层和变换，未知变换明确拒绝。

新生成器身份由原路径的独立命名空间计算，破坏物继续使用既有 ID。数据保留原初始树顺序；重设父节点后的实际进程顺序仍由正式场景拥有者负责，身份查找用的 map 不代表处理顺序。本候选没有修改存档、旧资源版本或正式场景 capability。

## 二进制与消费边界

尚未发布的 `ENCCF001` v1、capability 1 使用三节，当前5,607字节：

| 节 | 记录字节 | 内容 |
| --- | ---: | --- |
| metadata | 32 | 场景与来源、目标层、受支持的初始坐标合同 |
| instances | 64 | 稳定 ID、原 owner ID／路径、初始树顺序、局部／世界坐标、生成器来源、原目标及重设父节点、默认数量 |
| strings | 1 | 完整拥有且无重复的来源字符串 |

`CoinSceneData` 独立检查版本、capability、提交 pin、CRC、目录跨度、保留位、身份、顺序、有限坐标和字符串。随后与实际 `BreakablesData`／`CoinsData` 逐项匹配来源、owner、生成器、数量及位置；缺失任一实际绑定都不能启用。失败加载保留先前合法数据，成功重新加载增加数据代次。

`CoinSceneFactories` 只接收已经准备好的实例与父节点句柄。它核对 epoch、数据代次、实际资源对象、原句柄和两层父节点身份；已有效的单个工厂不能再次 prepare。Coin 请求必须对应实际 owner、原数量、已提交的原旗标和合法帧号，重复或未来请求拒绝。整批预检结束后只提交生成数量与开关，保持原计时和现有金币地址，其他已知请求保留原队列顺序；未知请求种类拒绝。

销毁前必须交付本拥有者的金币及子对象命令；其他对象的注册仍由其拥有者保留。这里没有把声音／HUD 请求写成实际生产音画已经完成，也不猜测完整物理树的事件顺序。

## 原版组合与本地验证

新观察器执行原49个木桶预制体及未改写的 Breakable、Flaggable、CoinSpawner、AbstractSpawner、Coin、Sparkles 和动画，使用原场景属性与位置。`Objects`／`Bottom2` 使用明确的单位变换 Node2D 测试父节点，替代本测试范围之外的 TileMap 地形；音频请求、HUD 和输入交付也是明确提供者。

两个独立原引擎运行均覆盖正序触发、逆序触发、首个原对象旗标已设置三种输入，各自产生147、147、144枚金币。每次保留42×49×3＝6,174份生成器逐帧状态、438份 Ready 记录、六个关键帧的所有金币状态及落地音请求。完整原始结果 SHA256 均为 `5c2661fdef82ce58ff7dd1e96b6e3bb8d4b24abe529ce21b9f45d3a9022d4054`。

`tests/coin_scene_source_tests.cpp` 实际运行移植的 Breakable → 具体生成器 → Coin 消费链，按源顺序比较计时、旗标、父节点、全部 Ready、关键状态、落地音帧和最终共享随机数；没有修改原记录或新增位置容差。本地普通泄漏检查的 GCC ASan／UBSan 当前通过282,774项组合、11,443项资源、273项消费者及6,094项既有生成器检查，包括资源对象／句柄归属保护。编译的是新模块并链接已核对的117模块旧核心归档，不称为完整核心重建。九项 Python 正反向检查已通过。

最初的观察器因编辑器把四个空格转换为 tab 而产生混合缩进，检查拒绝；失败记录保留，后续统一生成观察器缩进，原游戏文件不变。最初的重复事件负例错误构造了后一帧的新请求，修正为重放实际已发出的原事件；未调整玩法代码或原版预期来消除这项测试错误。

`compatibility/reviews/catacombs-coin-scene-v0410.json` 固定原来源、观察器、严格观察协议、转换器及两次真实运行。CMake 登记资源、消费者和原版组合测试，3DS 明确编译相同两个核心文件。完整 GCC／Clang、消毒器和真实 3DSX／CIA 仍待此候选的正式验收，模拟器开局回归不覆盖尚未接线的完整墓穴。

Windows Release 实际发现366项 CTest，包含新增四项及其 fixture 依赖；这是登记发现，不是完整执行。加入金币状态观察前后的旧字段也经独立投影逐项相同，旧原始记录仍保留。

临时产物维护已在核对 ELF、来源记录、文件哈希及运行进程后删除25份过期程序／对象，共187,959,576字节。所有日志、当前验证程序／对象、核心归档及模拟器游戏均保留，审计位于 `reports/coin-scene/cleanup/`。
