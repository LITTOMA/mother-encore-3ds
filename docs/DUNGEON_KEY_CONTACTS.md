# 墓穴钥匙的接触分派

本候选把 #77 的受检钥匙形状、已有采样接触组件与原版拾取方法接到一起。尚未由正式墓穴调用；没有新增资源格式、RomFS、保存编码或扩大可玩范围。

`DungeonKeyContacts` 只跟踪当前玩家身体与资源中 Pickup 矩形的接触。世界提供几何重叠；角色碰撞层、掩码、碰撞体是否启用，以及 `player.is_paused()` 的结果由现有玩家拥有者提供。它不是物理服务器、移动求解器或门交互选择器。按已有采样规则先交付上次物理采样的进入，再在移动后采样；禁用、删除或场景退役取消未交付的进入。暂停时发生的进入已被消耗，解除暂停并持续重叠不会重新拾取。钥匙隐藏与碰撞禁用保持独立，拾取后的延迟关闭由原方法状态执行。

所有对象、形状、过滤值和稳定身份来自独立资源。分派前检查不可变资源拥有者与场景代次。单次分派在接触与游戏副本上完成；后续拾取因请求容量失败，不会发布先前拾取或消费接触。没有进入事件的物理帧不会复制整个时钟世界。场景退役清理采样并拒绝旧代次；调用者仍须预留绘制、声音及旗标消费者后才发布最终场景事务。

实际验证：

- 两次官方 Godot 3.6.2，各14组／27个稳定观察结果一致。执行未修改的 Small Key／FlaggableObject 脚本、原生 Area2D／矩形和原版玩家八点碰撞多边形；玩家身份／暂停／移动、旗标／UI观察及音频占用／完成是明确服务，未运行完整地图、地形、绘制或真实音频。
- 覆盖普通进入／停留、其他身体、暂停进入后持续重叠、离开重入、禁用／重新启用身体、双向碰撞过滤、三个源钥匙的初始重叠、保存对象及外部音频完成删除。不声称与原版相同的精确物理帧延迟。
- 5901项直接 GCC 9.4 ASan+UBSan 检查通过，正常泄漏检查开启，实际退出码0，编译／执行输入指纹前后不变。包括全部原生观察、失效代次、独立资源拒绝、非法采样、退役及容量失败原子回滚。多钥匙容量用例是生产者不部分提交的不变量，不是当前地图能同时重叠两把钥匙的声明。
- 6项Python来源／对照／负向检查通过。Windows仅配置与发现得到310项CTest、1397项Python（1014汇总＋383专用），不是Windows运行通过。新提交完整GCC／Clang与真实3DSX／CIA仍待验收。

早期 native1／2 在场景重建前只改了节点位置，未等物理服务器同步，旧身体姿态污染了新场景：暂停、其他角色及禁用案例出现提前拾取，部分初始重叠还拾取了两把钥匙。现先在没有钥匙的空场景中完成物理同步，再创建下一组对象，并核对每组声明的初始计数。修正的是对照程序初始化，没有改原脚本、规则或共享核心期望；早期原始观察和适配器均保留，新的验证器拒绝缺失／不符的初始状态记录。native3／4作为当前独立对照。

完整证据在 `reports/dungeon-key-contacts`。生产纹理、正式地图／UI／存档以及 Pippi 救援继续待接入；以上不构成新地图的模拟器、音频听感或真机验证。
