# 墓穴脚步声区域与阴影回调候选

固定上游为 `7d9246600fffe518408f5830d4848635019005a3`。本候选补齐三个原脚步声区域的独立数据、凸多边形表示、共享核心回调和阴影模式状态；正式墓穴场景仍未接入。不能据此声称墓穴可玩、阴影已显示或八种脚步声已经由 NDSP 输出。

## 原版依据与行为

来源为 `Catacombs.tscn`、`stepping sounds.tscn`／脚本、Player／PartyObject 的所列方法、完整 `Shadow.tscn`／脚本、三张原图及八种原脚步声媒体和导入设置。34 个来源文件及原许可指纹由 `content/catacombs-stepping.json` 核对，没有环境字体、工具或缓存进入游戏资源。

原 Player 的初始跑步声是 wood。八种继承选项均保留：grass、stone、soil、sand、wood、metal、water、cave。水域进入选择 water，离开选择 stone；土地区域进入 soil、离开 stone；石地区域进入 stone，离开不改。改变选择只更新 wanted sound；实际跑步调用才决定是否替换播放流，原有 MOVE、暂停与门状态分支继续复用既有 FieldRunLoop。

声音赋值仅作用于当前玩家，且要求区域 enabled。阴影赋值作用于任何 PartyObject，独立于 enabled；其他身体不改阴影。空的退出阴影保持原状态。原版反复设置相同模式保留当前帧，切换模式重置到第零帧并播放；ripple 位于角色前，其他模式位于角色后。共享核心没有实现随时间推进 Shadow 帧，也没有模拟完整 Player／PartyObject。

水域的 11 个原多边形、土地区域的一个原多边形、石地区域的一个原矩形全部保留。98 个原始顶点分解为 23 个原引擎凸形状；包围框只作元数据核验，不能代替接触几何。原版观察包含水域包围框的四个内部角点和中心，五处都不与实际水面重叠。物理过滤也检查双向位匹配：身体 layer=2／mask=2048 或 layer=0／mask=2048 仍能与水域接触；layer=2／mask=4353 不接触。

## 资源与执行边界

`ENCSTEP1` 保持 format1，新增独立 capability2，候选 2,748 字节。旧 capability1 的矩形、容量、保留字段和旧生产器保持原规则；旧 Python 读取器拒绝新能力，新生产器拒绝旧能力。游戏存档、目录角色、正式 RomFS 和既有生成资源均未改变。

新能力使用 176 字节头及七个分区，步长为 1／24／56／72／16／8／32，分别保存字符串、初始策略、声音、区域、凸形状、顶点、Shadow 模式。区域有稳定来源 ID、连续拥有的凸形状跨度；顶点与跨度不能孤立、越界或交叉归属。来源 pin、CRC、目录、路径、坐标、凸性、重复顶点、包围框、模式声明和所有保留位均严格校验，失败保留已加载状态。FPS／帧数／循环和前后层次来自资源，C++ 没有游戏内容表。

`apply_step_callback` 检查身体分类和同一份数据的 Shadow 所属关系，再原子提交声音与对应身体的阴影状态。`FieldStepShadowState` 实现有界模式／帧选择。`step_polygon_overlap` 是包含相接边的理想凸多边形查询；调用者负责身体筛选、物理采样和原引擎接触余量。当前稳定原版样本吻合，不将它称为对所有边界／时序的完整物理服务器复现。

实际 `FieldScene::bind_steps` 在其他绑定之前拒绝 capability2，报 `Polygon stepping requires a matched contact and Shadow consumer`。旧场景仍使用其受检矩形路径；正式接线须先实现匹配的接触和 Shadow 绘制服务，不能回退成大矩形或略过未移植内容。

## 实际验证与保留证据

- 原 Godot 3.6.2 两次全新回调项目，各 60 个跑步声／区域／Shadow 观察；完整原 Shadow 的三套帧、顺序、速度及循环也吻合，结果逐字一致。
- 两次全新物理项目，各 41 组、164 个稳定观察；实例化三个原样区域与 13 个形状，用原玩家八顶点和本地原点验证分解、初始重叠、禁用、其他队伍成员／身体、筛选与包围框反例，结果逐字一致。观察器不假定先于或晚于原信号回调，结论比较物理稳定后的状态；不比较确切帧延迟或动画相位。
- 当前全部 116 个共享核心源文件重新编译，GCC9.4 ASan+UBSan、正常泄漏检查：新增 12,743 项通过，未修改的旧矩形／跑步声测试 1,353 项通过。包含实际旧场景入口拒绝、截断／未知版本／模式／所有权、退回失败原子性及全部稳定原版几何／回调观察。
- 19 项 Python 通过，其中新增 12 项，旧脚步声／跑步声来源七项。Windows 只配置并发现 326 项 CTest、1,452 个 Python 方法＝1,069 聚合＋383 专用，不把发现当作执行。
- 当前提交的完整 GCC／Clang 矩阵、真实 3DSX／CIA、该产物模拟器、Shadow GPU／NDSP 及真机尚待验证；原版回调使用明确的身份、SFX 状态与暂停／门服务，不宣称有可听输出或完整根场景。

证据位于 `reports/catacombs-stepping/`，包括两个最终原引擎结果、实际输入与适配器、早期失败、来源映射、编译／消毒器／发现日志及清理审计。最初直接复制 `.import` 遇到未附带的缓存；随后只改参数未导致缓存重建，原纹理标志断言失败。固定引擎实际重导入后才通过，未压制警告或修改历史期望。重导入方法依据 [Godot 3.6 的来源／目标 MD5 检查](https://github.com/godotengine/godot/blob/3.6/editor/editor_file_system.cpp#L385)，只删除本次新项目生成的 11 个小型校验记录，保留缓存供编辑器读取原设置；没有复制开发环境导入缓存。

十个原版临时项目和 116 个已与归档逐一核对的重复目标文件，共回收 475,242,591 字节。第一次清理在删除前因所有权标记使用 Windows CRLF 而拒绝；核对原创建脚本及准确字节后才重试。原始日志、观察、适配器、当前核心归档和实际游戏均保留。
