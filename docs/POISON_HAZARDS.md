# 墓穴毒液回调与喷口调度

本组件保留原版 11 个毒液区域的触发／阻挡多边形，以及 37 个喷口的计时和延后生成请求。共享核心已与实际原引擎的逐帧结果对照；完整毒液伤害、喷口演出和墓穴场景尚未接入，当前可玩范围不据此扩大。

## 数据与来源

固定上游 `7d9246600fffe518408f5830d4848635019005a3`。`content/catacombs-poison.json` 审查 11 份来源，包括地图、毒液／喷口场景、所选原方法、PartyObject、Status、脚步声与许可；区域、喷口的拥有者和顺序必须完整匹配。`compatibility/reviews/poison-hazards-v0410.json` 映射实际实现和两次原引擎结果。

独立 `ENCPSN01` format1／capability1 为 6,360 字节，保存源身份、中毒字符串、两套伤害请求参数、零方向、生成偏移、37 个间隔／延迟、11 个区域、22 个形状及 178 个原始顶点。它没有加入正式目录、RomFS 或存档；各版本域保持独立。C++ 只包含 schema、校验和执行，伤害值、来源路径、声音目标与调参在资源中。没有复制字体、游戏媒体、工具或固件。

两个碰撞多边形分别属于 Area2D 与 StaticBody2D，原顺序、局部顶点、位置、层与掩码均保留。加载拒绝重复或自交／退化多边形、未知版本／能力、错误来源、字符串别名、越界／未拥有数据、非法计时类型与下溢延迟。这里保留的是原始多边形，没有把它称为已实现完整物理或凸分解。

## 原方法行为

毒液进入只接受 PartyObject，且以当前玩家的暂停状态为门控。接受后设置持续伤害、原攻击值／变化范围，请求 `Character.add_status`，再转交原脚步声回调；不是只对当前玩家造成请求。退出在暂停时仍停止持续伤害并转交脚步声，不清除中毒、不清空记住的伤害参数，也不按其他重叠区域计数。喷出的毒液使用另一套原参数，且不转交脚步声。

`apply_poison_callback` 在绑定和整次回调成功后才提交伤害请求、Run 与 Shadow 状态。未知种类／身体／拥有者、错误 Shadow 来源或请求容量耗尽均拒绝，不部分提交。原 `start_continuous_damage` 没有保存 `hit_direct`；本模块没有额外创造方向副作用。状态列表是有序的 add_status 请求，不是已实现的 Character 状态效果。

`PoisonHoleTimers` 保留原生 Timer 的 binary32 间隔和 double 剩余时间，只在剩余值严格小于零时触发；每次处理最多一次超时。原生 Timer 在信号前用旧间隔重新计时，原回调随后才把未来间隔改为 interval。因此初次短延迟后的第二次触发仍受旧值影响，不能直接改成每四秒重排。相关官方引擎源码、Git blob／SHA 和 MIT 声明在 `reports/poison-hazards/engine/`。

玩家暂停信号与 SceneTree 暂停分别处理；隐藏喷口不停止 Timer，准备时也不根据一个注入的玩家暂停布尔量擅自暂停新节点。生成请求带场景代次、单调票据、源拥有者及源局部位置加偏移。它保留原 `call_deferred(add_child)` 的请求含义，没有自动实例化未批准的完整喷口场景。队列满时整批拒绝并保持原计时与请求。

## 实际验证

官方 Godot 3.6.2 两次各运行 720 个固定 60 FPS 的实际计时帧、99 个手动原回调、102 个实际延后添加的 Node2D，并观察所有 22 个形状的全局顶点。两份完整结果逐字一致，SHA-256 为 `fa56df37430f14388f4b1959990921a1c2320ec1806aced31541ab7869e03c06`。

观察使用真实 Timer、完整原 Poison Area 场景／脚本、所选原方法与实际 PackedScene 延后添加；玩家／信号、PartyObject 身份、Character.add_status、set_shadow 和生成工厂是明确的服务。计时动作在本轮 internal Timer 处理之后投递，超时顺序与最终添加节点分别记录。没有运行完整玩家、Character、喷口动画／声音或自动身体接触。

早期缺少全局类声明、服务信号未在类内发出和原方法未使用参数触发编译诊断，均保留日志。通过声明实际所需类和服务发射方法解决；原伤害方法只追加一个观察器局部量读取未使用的方向参数，不改原赋值，也不屏蔽编译器诊断。第 4／5 次观察结果虽然一致，留档发现编辑器重写了临时项目配置，输入指纹验收拒绝。最终第 6／7 次保留编辑器中间配置，再恢复受检文件执行，并在执行后逐项核验。原始失败与实际适配器保留在 `preliminary/`。

- GCC 9.4 ASan／UBSan，正常 `detect_leaks=1`：最终 117,974 项通过，逐帧比较所有 Timer、超时顺序、延后位置和回调状态；覆盖损坏资源、错误来源、回调失败保持、旧场景代次、长帧／零帧和队列满的整批回滚。首轮 117,855 项通过记录也保留。
- 实际编译新生产模块与测试，链接输入未变的 117 文件核心归档；不是本地全 119 文件重编译。未使用 NDSP／图形替身来声称这部分通过硬件。
- 14 项 Python 通过（32.203 秒），覆盖来源、编解码、非法多边形／计时、原观察拒绝、冻结双结果和夹具复用／篡改保持。
- Windows 仅配置和发现 334 CTest、1,493 Python（聚合 1,110、独立 383），没有算作执行。

完整当前 GCC／Clang、真实 3DSX／CIA、新产物模拟器及真机尚待运行。正式场景仍没有批准本能力；HP／RNG／状态效果、持续伤害 tick／闪烁、完整物理、喷口动画／空间声音／可见性／震动和 Pippi 流程仍须继续实现。

七个原引擎临时项目与已替代的首轮测试程序经精确路径、归属、逐文件哈希、重解析点与进程核验后清理，共 5,585,224 字节。原始失败／通过记录、实际适配器、当前测试／核心归档和游戏保留；清理凭据位于本组件报告目录。
