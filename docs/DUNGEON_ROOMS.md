# 墓穴房间状态与镜头边界

新增的 ENCDRM01 format1／capability1 单独保存固定上游的十八个墓穴房间：稳定拥有者、实际兄弟索引、探索旗标、区域形状、镜头尺寸、碰撞过滤和原版重置边界。来源审查包括八个文件、实际 Catacombs 根脚本的继承关系，以及原版房间、镜头和旗标方法。根脚本的开关／墙门逻辑继续由父分支的机关模块负责；本资源不因此批准整张地图的其余节点。

`DungeonRoomState` 执行受检的进入／退出协议。首次进入请求设置实际 object flag 并广播更新，立即选择当前房间并重置镜头范围，再等一次空闲帧应用区域限制。退出时仅在没有其他活动区域时重置范围；不会自动选择另一个仍重叠的区域。当前房间编号在退出后保留。若同一帧先进入、退出再进入，原版两次等待会在空闲帧都看到 `inside=true`，因此两个继续执行请求均保留。

所有区域均来自隐藏的 `Rooms` 父节点。隐藏不等于禁用 Area2D。原版编号取实际兄弟索引，地图相对位置减去碰撞形状的全局中心，而非 Area2D 根位置。旗标覆盖必须完整；未知拥有者、重复进入、不匹配退出、旧 epoch、无效视口、队列超限及退役后的回调均明确拒绝。失败保留状态、旗标、事件和待执行继续；再次准备需要更新的 epoch。该模块输出受检请求，尚未替代正式场景的旗标／镜头消费者，也没有新增存档身份。

同时修正现有 `FieldScene` 的镜头边界计算。原版先按视口扩大较小区域，再计算边界，并通过 Camera2D 的整数属性截取。原代码提前用未扩大的尺寸计算左上角；同一份原版观察在 400×240 视口下，旧消费者得到 `(-848,64)`，原版为 `(-848,56)`。新公共计算还保留负坐标边界的精度：十八个房间中第八号区域的原版上界为 `-591`，不能先按 binary32 标量运算舍入成 `-592`。这只修正已有区域的空间投影；现有 `FieldScene` 的区域选择／交接策略和新墓穴状态的正式接线仍待后续工作。

验证范围：

- 两次原版 Godot 3.6.2 运行，原脚本、原生 Camera2D 整数属性、十八个实际区域及隐藏父节点；140 个方法／空闲帧观察与 36 个原生几何记录完全一致，覆盖 320×180 和 400×240。玩家身份、场景继承和进入／退出投递是明确的测试服务，未模拟完整物理世界。
- 5465 项 GCC 9.4 ASan+UBSan 检查通过，包含数据编解码拒绝、探索旗标、当前／相对房间位置、交叠、取消、同帧再次进入、容量失败回滚和场景退役。正常泄漏检查保留。
- 准备后的 `FieldScene` 用同一原版结果通过 290 项检查；旧消费者在同一用例明确失败，新消费者通过。既有 AreaRoom 663 项消毒器回归通过。
- 七项 Python 来源、双运行一致性、编解码与未知继承／属性拒绝检查通过。补齐实际根脚本依赖后，通过原生成器重新运行；二进制资源、全部 140 项观察和三份 C++ 夹具输入逐字不变。
