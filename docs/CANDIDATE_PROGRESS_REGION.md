# 加载指示器、启动准备与精确区域采样

## 固定加载指示器

加载人物固定在左下角，不再以水平移动表示进度。默认 400×240 下位置为 (8, 203)，320×180 参考模式为 (8, 143)；边距、31×29 图素帧与 0.8 秒动作循环继续来自受检资源。人物保持原尺寸和动画，只按加载墙上时间取帧，不推进游戏时钟、输入或随机流。

加载画面最多每 50 毫秒更新一次（20 Hz），减少同步资源读取 callbacks 内的 GPU 帧提交。每次加载仍保留明确任务计划与失败状态；完成数和任务比例仅用于开发日志，不决定人物位置。最终提交失败不会报告成功。

## 启动准备

进入标题前仍核对资源目录及二进制文件的大小 / CRC，读取房屋、战斗、回合、物品、存档恢复与会话元数据，准备标题 / 菜单、所选语言字体、输入及 NDSP 流式后端，并扫描已有存档。音频初始化不再扫描所有 PCM：只完整校验并保留标题音乐和四种标题菜单音效的流句柄；首次请求其他音轨时再完整校验其大小与 CRC，校验失败不能提交 NDSP 播放缓冲。已准备音轨重用句柄，不重复校验。加载 callbacks 继续补充当前已播放音轨的缓冲，不推进游戏 / 淡出时钟。大音轨首次准备仍可能等待，加载人物在这一阶段也会显示。原版 Introduction 的图像在开始演出时准备。当前音频 receipt 的 21 项合计 62,317,300 字节；标题所需 5 项为 22,355,322 字节，启动 PCM 完整扫描量减少 39,961,978 字节（约 64%），这不是总启动耗时的测量。

标题与命名共用已有的仅字体加载路径，启动不再准备战斗背景、掩码、演员图集、400×240 战斗工作缓冲或回合演出纹理。房屋地图、人物 / NPC、物品图集及房屋声明的音频在 New Game 或 LOAD 的房屋提交前一次性准备，缓存后不重复读取。二进制语义校验和存档兼容检查保留；准备失败不能提交新场景。

战斗资源继续由现有房屋场景 admission 准备并驻留，包括遭遇音效的 PCM 校验，在允许房屋游玩前完成。遭遇请求处不增加加载屏幕，不提前选择随机敌人；枕头 GPU 纹理条带配置保留。这减少启动和命名期间用不到的资源准备，也避免准备整套首战资源后立即为命名释放，但仍可能在进入房屋时等待资源。

默认构建向设备调试输出记录 `ENCORE_LOAD_TASK`（scope、任务、资源类别、耗时、成功状态）和 `ENCORE_STARTUP_READY`（从入口到标题准备完成的总耗时）；QA 构建另保留任务日志。不在发布 RomFS 中保存日志。当前改动没有设备启动时长的前后测量，不能据此声称具体加速倍数。

## 精确区域采样

`RegionBackgroundKernel` 使用既有受检图像、调色板和输出偏移，证明支持的常色区域；仅当保守坐标包络完全落入该区域时省略逐点采样。不支持的形状、参数、时间、分配失败或资源上限继续使用精确基线 sampler，不能静默采用近似图像。

区域、斜率与行缓存有界；源图像和 GPU 输出 ownership 不变。浮点构建保持禁止 contraction 的对照约束，不启用 fast-math 或 reassociation。可选 GPU 路径按各自开关与证书检查运行；本页的 CPU 区域测量不能推广到这些路径。

## 局部测量

隔离 ARM 原型针对 REGION32 与 AFFINE32 对照了 1,228,800 个线性像素和 8,388,608 个映射字节。400×240 REGION32 的 mapped CPU 时间为 32.839–37.553 ms，对照 sampler 为 51.844–60.360 ms。

这些是特定原型和 Azahar 配置中的内核测量，不是当前完整游戏 FPS、真机性能或原版 Godot GPU 像素等价证明。后续资源上限、生产接口或 GPU 路径变更须重新验证相应范围，不能直接沿用原型数字。

## 验证要求

保留 host / sanitizer 的像素与失败注入对照，以及真实 ARM 构建。完整帧性能要分别记录准备、采样、编码、上传和 GPU 提交耗时，并测量临时内存与驻留峰值。加载任务位置和完成端点需通过实际入口检查。当前支持范围与硬件限制见 [STATUS](STATUS.md)，构建与测试入口见 [BUILD](BUILD.md) 和 [TESTING](TESTING.md)。
