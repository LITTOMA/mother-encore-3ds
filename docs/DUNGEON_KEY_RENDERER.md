# 钥匙与锁门图像准备候选

来源固定为 `7d9246600fffe518408f5830d4848635019005a3`，沿用已审查的 `ENCKMP01` 媒体、六对象和三个图像配置。生产服务在 `platform/ctr/dungeon_key_renderer.hpp`，共享核心仍生成图像帧、连续位置、可见性和原版层次；没有新增游戏内容常量、资源格式、正式 RomFS 或存档变更。该服务尚未创建于正式场景，不据此开放墓穴或声称 Pippi 已实现。

准备时逐张读取资源路径，检查实际长度与 CRC，再将同一份已校验字节交给 Tex3DS；不重新打开文件，也不借用仅按路径查找的全局纹理缓存。三张纹理及其元数据全部通过后才发布资源归属。缺文件、字节损坏、导入失败、多个图像、缺失子图、尺寸、旋转或无效 UV 均拒绝并释放候选。来源 SHA 用于生成与离线凭据；运行时字节 admission 是长度／CRC，不冒称运行时 SHA 校验。

每帧从同一资源和场景代次取得只读绘制快照，保留父节点、场景顺序、Y 排序和深度，供场景与地形／玩家合并排序。调用方提交快照索引，服务保留实际子图的 UV 起点与范围，应用帧裁切、翻转、1:1 坐标和相机位置；没有擅自把整张地图按对象扁平排序。纹理使用最近邻过滤、透明边框。绘制不读盘、不重新解码或分配纹理；快照本身仍使用共享核心的容器，不声称逐帧零堆分配。

旧帧、错误资源／场景、无效索引／相机和退役调用均拒绝。开始新帧会使旧快照失效，失败也不继续画旧帧。退出在调用方的 GPU 空闲边界释放全部纹理，下一次准备要求递增代次；绘制前显式刷新批次和绑定实际纹理，避免对象地址复用时沿用旧 GPU 缓存。单次绘制队列失败会报告给调用方，不声称能回滚已提交的整帧 GPU 命令。
