# 场景对象的独立资源与生命周期

当前只完成共享核心的独立数据加载与 DroppedItem 的进场、空闲帧及删除子集，尚未接入正式地图、取铲剧情、领取道具或 3DS 绘制。树根打断及 Pippi 救援仍待完成。C++ 不保存铲子的路径、旗标、位置、帧序列或调参数值；测试夹具从已记录的固定上游审查及真实纹理转换记录构造。

ENCFOB01 使用独立 format1 / capability1，五段分别保存文本、纹理身份及尺寸、稳定对象记录、矩形帧和动画序列。当前仅接受已映射的 DroppedItem 种类；交互模式必须为零，不能据绘制记录推导已实现的拾取行为。加载检查来源 pin、校验和、全部保留位、规范段布局、已消费内容、身份及路径唯一性、有限数值、动画范围与 Room 场景／旗标域。未知版本、能力、种类、交互和坏引用明确拒绝，失败不覆盖原对象。

prepare 只验证和建立拥有者，不消耗随机数。调用者必须按原场景树顺序逐个 enter_ready，并与其它节点的 Ready 交错；Sparkles 子节点先执行原版全局 rand_range，再由 DroppedItem 父节点检查进场旗标。即使父节点被旗标抑制而加入删除队列，子节点的随机调用仍发生。序列帧先截断整数，再按 AnimatedSprite 的帧数夹紧；没有另建随机流。

原 DroppedItem 的 hide、等待 idle_frame、show 与显式 queue_free 分开。原剧情设置 got_shovel 不会立即隐藏现场铲子；对象只在进场检查此旗标，或收到明确删除指令。queued 对象在删除队列提交前仍然存在。隐藏状态及玩家剧情暂停不停止其子 AnimatedSprite；时钟保留原 Godot 3.6.2 的 binary32 remaining / timeout，以及下一次处理发现 timeout<=0 才切帧的顺序。

原引擎探针使用未经修改的 sparkles.gd 和逐字提取的 DroppedItem._ready；隔离了旗标读取、Player 信号连接和纹理赋值依赖，不代表完整节点继承或原游戏运行。实际499个观察点包含32种种子在进场旗标真／假两种条件下的帧夹紧与后续 randi、430帧动画、延迟显示、运行中旗标改变及队列删除。来源、原始日志与脚本保留在 reports/iggy-tutorial/field-objects-reference-1。

Room 的 C++／Python 消费者另加入 capability14 与唯一新增指令49 QueueFreeStoryObject。target_index 是精确来源节点路径的字符串索引，其余 actor、flags、vector、value、duration 和辅助字段必须保持未使用值。旧13拒绝49，14必须实际含有删除指令，未知15拒绝。它只调用专用场景对象接口，不提供任意节点方法执行。

OpeningWorld 先按场景和元数据路径绑定拥有者；每次启动相关节目又检查对象已Ready且存活，才允许进入剧情、设置旗标或消耗随机数。运行到指令时再次检查，记录在与原有对象方法共用的延迟队列；段落处理结束后才调用queue_free，再由场景提交对象删除。静态绑定不会要求对象永远存活，因而旗标抑制的再次进场仍能准备场景；不满足现场条件的节目不能启动。中途删除失败明确进入错误状态，不跳过指令或伪称完成。场景拥有者负责实际删除队列提交，World不暗中提前释放。

原版 gravedigger_getshovel 的0段旗标与3段删除被编译为独立顺序夹具，用于验证“已写旗标但物件仍可见→队列删除→场景提交”。它不包括完整对白和演员路线，也没有额外发放Shovel。当前正式Room仍是13，尚未发布包含49的正式取铲节目；Session、规则和游戏存档格式不变。

GCC9.4 的 ASan/UBSan（泄漏检查）通过元数据187项、生命周期3022项、删除拥有者／指令95项及旧球棒授予59项。Python新增／旧授予／引擎来源9项、原Room解析26项及源文件表3项通过；完整方法收集1197项。实际日志、完整核心重编译指纹、版本及失败记录单独保留。CMake 与控制台 Makefile 使用同一执行文件；Windows仅配置及方法收集，不宣称 Windows C++、当前交叉构建、GPU、模拟器或真机通过。后续正式接线仍须完成地图／绘制／完整剧情资源迁移。

后续来源复核发现，DialogueBox.gd 对不带参数括号的 objectsfunction 使用 call_deferred。新增内部时序回归在 ffbd 原核心失败：队列方法看到PC4，原版需要先经过随后的YieldIdle，看到PC5。修正仅将49纳入已有的有界延迟方法队列，保留方法间顺序、执行时再验证和独立删除提交；没有改旧期望或正式游戏数据。95项专用检查通过；旧FieldStory11690项及教学／Session／Restore消毒器回归也通过，原始失败／修正记录保存在 story-object-deferred。
