# Catacombs 原版地形候选

本组件从固定上游 `7d9246600fffe518408f5830d4848635019005a3` 提取墓穴五个 TileMap 的绘制几何、原碰撞形状、逻辑格子与导航多边形元数据。它尚不能创建可游玩的墓穴场景：根脚本、角色／AI、剧情、导航求解、正式资源目录与存档接线仍待实现。没有修改原版、既有地图版本、资源目录或存档 schema。

## 来源与原引擎对照

`content/catacombs-terrain.json` 审查完整场景、TileSet、两份动画纹理、八张源图、原玩家碰撞设置、项目设置及原许可。素材沿用原许可，不带入开发环境字体或第三方程序。两个原引擎 3.6.2 冷启动只加载五段原样 TileMap 节点及原 TileSet／纹理，隔离观察器没有执行完整地图根脚本或角色。两份 `terrain.json` 逐字一致，各含 12,248 个原始格子的身份、翻转、自图块坐标、图层设置以及全部 30 个图块定义。

原 TileSet 挂有空的 GDScript SubResource152：原引擎报告无源码、不能实例化、无基类与方法／属性／信号。适配器只接受这份已核对的空资源，不新增通用脚本执行器。24 号 SpikeGrounds 在八个格子实际使用原四顶点导航多边形；数据保留该几何，不把它冒充导航求解器。Bottom1 的 (-42,1) 原本引用没有定义的 11 号图块，原引擎仍返回这个逻辑格子。因此逻辑层保留它，绘制／碰撞层没有捏造图块：12,248 个逻辑格子对应 12,247 个可绘制格子。

灯笼和毒地板动画沿用源帧序、速率及既有图片机制。对照不包含纹理时钟相位或画面像素一致性，不能据此宣称 GPU 或完整碰撞运动已对齐。原导出器仍对脚本／导航失败关闭；本次仅在新的受检适配器里分离已审查的元数据视图，不放宽旧生成器或其来源记录。

## 独立格式与入口

`ENCTERR1` f1/cap1 的 527,412 字节外层资源有九段：UTF8 文本、嵌套地形绘制数据、来源元数据、图层、逻辑格子、原图块定义、导航多边形、顶点及索引。每段有固定步长、完整所有权、来源 pin、CRC 和容量／编码检查；失败不替换已加载的状态。导航只提供只读记录。

嵌套 `ENCTMAP1` f1/cap1 为 132,156 字节，复用原地图的图像／几何编解码和渲染数据结构，只有图层绘制，不带玩家、精灵、对象、门、条件或其他场景行为。其身份与 `ENCMAP01` 独立，旧格式的能力 1–6 及玩家要求保持不变。真实 `FieldScene::prepare` 明确拒绝 `ENCTMAP1`；改魔数或插入场景行为也不能绕过新格式校验。C++ 只保存 schema 与执行机制，源内容和图层身份来自受检二进制。

候选只生成到新的 `build/` 目录。实际 tex3ds 已转换一张 1024×256 RGBA8 图集（1,048,597 字节）；CLI 输出的两个资源与消毒器使用的数据逐字一致，并拒绝向 build 外写入。没有手改 pack／manifest，也没有把候选加入正式 RomFS 或发布素材。
