# 多场景资源选择（开发中）

市政厅需要第二套 Field Room／Map、NPC 和音乐。原资源目录的这些类型绑定为单例，直接覆盖全局加载器还会使旧场景持有的 view 失效。因此先增加受检引用，再实现平台资源生命周期与实际场景内容；目前尚未增加市政厅可游玩范围。

目录容器格式仍为 1，能力 9 才允许 FieldRoom／FieldMap／FieldStory／FieldMusic／FieldAudio／FieldMusicZones 的额外绑定（独立 ID 从 1024 起）；原单例 ID 必须保留。其他类型与旧能力的限制不变。`path(role,id)` 按类型和身份查询，错误类型不能得到路径。旧资源目录目前仍生成能力 8、47 项，输出字节保持不变。

World Links 格式仍为 1，新增能力 2 的 SceneAssets（36 字节）和 NpcBindings（4 字节）两个节。每个 Field Scene 恰有一条资产记录；NPC 引用必须有唯一的范围归属、无重复或遗留项；音乐三项齐全或全空。绑定目录时验证每个资源类型，并拒绝目录中无人拥有的场景资源。能力 2 可表达同场景门移动；能力 1 保留原来的拒绝规则和单场景目录解释，遇到多个字段资源集必须拒绝歧义。

测试旧夹具直接取自已构建提交 cbdd992 的目录与 World Links，没有改写其字节。新增第三场景仅为编解码夹具，不是原版地图。GCC9 ASan/UBSan 的新元数据 66 项检查、已有目录 5,426 项和桥头剧情回归通过；三个 Python 测试覆盖版本、身份、类型、缺失默认项、截断与能力不匹配。日志在 reports/field-scene-resources。此阶段未更改规则或游戏存档格式；交叉构建与模拟器结论另行记录。

待完成：来源 Scene 编译与路由；原版市政厅图层、碰撞、内部门、音乐和初始 NPC 对话；新平台切换的实际输入路线及负向加载恢复。不能在旧 FieldScene 仍活跃时覆写其 Room／Map 数据。

资源生命周期基础：新增不可重新加载的 FieldSceneResources，按类型／身份读入并验证目录长度与 CRC，拥有 Room／Map／Story／Mick／NPC 和区域音乐元数据；核对场景 ID／来源、共享旗标域、NPC 子类型和音乐／音频绑定。原目录与 Links 销毁后，已加载元数据仍保持独立有效。失败不发布半成品；已有场景的 view 不被下一次 load 覆写。新增 32 项 GCC ASan/UBSan 检查通过，平台接入仍在开发。

平台现在按门的目的场景选择并先加载独立元数据，再准备借用 view 的 FieldScene；候选 bind 的旗标主机优先指向候选场景，只有提交时才替换旧所有者，所有退出路径按 Scene→Resources 顺序销毁。Mick／NPC 与剧情音效也从候选所有者读取。平台已接入跨 Field 的独立资源及音乐候选，实际市政厅可玩资源尚未生成。

跨场景区域音乐基础现允许各声音租用不同的 NDSP 4..19 声道；0..3 仍属于既有 AudioPlayer。准备不占用声道，播放前先完整验证所有目标和声道分配；物理容量不足不清除任何已有队列。跨场景必须先送原版 tree_exit／finish_scene；随后原子移交候选，旧服务继续拥有独立文件、缓冲、控制器和淡出时钟，新服务拥有新曲目。转移 unique State 保持播放器与控制器地址稳定；别名所有者、未准备候选、旧候选、错误 epoch、外部 DialogueMusic 冲突均拒绝且不发布半次移交。纯 refill 接口补充旧区域队列而不推进淡出、改增益或重启曲目。原版依据为 Nodes/Overworld/MusicChanger.tscn 的 tree_exiting→stop_music 及全局 audioManager 保留播放器的淡出行为；不是任意等待淡出结束后再开新曲目。

GCC9 ASan/UBSan 实际通过区域播放器 774、生产服务 960、增量准备 46,894 检查；后者保留真实 77,419,288 字节 CRC 读取与慢读取模型（9,462 步，零模拟欠载，非硬件时序）。新增两所有者并发、完整 16 声道耗尽保留、回收复用、暂停、加载 refill 和负向原子提交。首次故障注入暴露重试放弃原槽，已改为保留可复用声道提示；原失败日志保留。此基础接口尚待平台实际调用及模拟器验收，不据此声称市政厅或实际音频通过。

平台切换现使用新资源所有者，准备新场景时保留旧所有者；House／Field 与 Field／Field 共用受检目的选择，保留活动场景的旗标和 House 存档位置。不同音乐集先校验候选、保留旧曲独立淡出；同一音乐／音频集继续使用现行控制器保留原曲相位。候选拒绝时原子恢复源控制器的注册、voice 和 fade 状态，加载期间同时 refill 所有活跃队列。退出应用／新游戏／标题释放全部退休所有者。原版 audioManager.pause_all_music 会先完成 tween 再清理静音播放器，因此战斗前先完成退休淡出，不让旧场景音乐带进战斗。回屋图形切换在失败时恢复旧 Field 图形。

同地图门只调用共享 FieldScene.warp_route，核对路由索引、源／目的场景和过渡状态；零方向沿用玩家方向，保持 NPC／旗标／RNG／音乐，更新 B 返回安全点并抑制目的门的立即重入。实际 Podunk 元数据加内存合成内部门的 20 项 GCC ASan/UBSan 检查通过；不是新增原版楼层的验收。扩充后的音频服务 1,034 项和此前播放器／增量准备检查，以及资源所有者 32 项已再次通过；源指纹和日志见 platform-handoff-source.json。此前 3dbccbe 平台资源接入的真实交叉构建已通过；本段新增 API 的控制台与模拟器验证仍待记录。现有实际资源仍为目录能力 8／Links 能力 1，市政厅未开放。
