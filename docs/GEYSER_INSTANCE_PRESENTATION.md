# 工厂喷泉的声音与绘制接线

本候选把 `GeyserLifecycle` 生成的实例交给已有PCM混音器和纹理绘制器。实例不再需要另建一份独立动画对象才能发声或绘制；仍未接入正式Catacombs场景、角色物理接触或Pippi流程，可玩范围不变。

## 来源与兼容

沿用固定上游 `7d9246600fffe518408f5830d4848635019005a3` 的喷口、喷泉、动画和声音方法，以及已审查的生命周期、声音和图像资源。没有新增内容常量、素材、字体或第三方二进制。三个独立资源格式、能力、规则兼容、正式资源目录和存档均不变；生成器和原引擎观察输入也未修改。

工厂与媒体分别加载元数据，不能把两个不同资源所有者误当成同一指针。桥接先核对完整来源内容一致，再在当前场景绑定生命周期资源所有者；同一场景内不能混用手动实例与注册表。修改后的有效元数据、外来所有者、旧代次、尚未Ready或已销毁实例都有明确拒绝路径。

## 声音交付

`GeyserMixer::sync_lifecycle` 事务性接收整份注册表：绑定Ready实例，更新当前空间增益及暂停状态，按原跨实例顺序执行声音传输，并移除已显式销毁的局部声道。全部验证通过后才消耗命令并提交混音器；未知命令、错误实例、监听坐标、容量或未提交的输出缓冲都不会部分提交。

全局命名声音继续由独立所有者控制，局部实例或整个场景销毁不自动停止它。新增接口直接复用既有PCM缓存、输出缓冲、用户音量和自然结束确认，不重新读文件。生产 `GeyserAudioService` 提供相同桥接，BGM仍由既有播放器维护。

坐标遵循已有的平移监听配置：注册表位置属于原工厂父节点，camera和listener也必须使用该父节点坐标。固定原地图Objects无额外变换；正式场景所有者仍须核对或转换坐标，不能把未知旋转、缩放或多视口当作支持。

## 绘制交付

`compose_lifecycle` 从同一实例快照取得帧与根位置，不再次叠加预制场景的根偏移。生产绘制器的新重载借用同一份纹理，在提交时重新核对注册表对象、场景／帧代次、实例、动画时间与位置。克隆所有者、动画已推进、相机变化、重复提交和销毁后的旧绘制令牌都不能提交。

## 实际验证

- 最新核心检查：GCC ASan＋UBSan、正常泄漏检查，1,872,115项通过；重放两种树顺序各720帧的既有原版记录，比较实例属性、声音顺序、PCM声道语义与CPU绘制投影。每种顺序的原记录各有两次实际原引擎运行，本候选没有新增原引擎运行。
- 生产绘制检查：3,491项通过，输入实际T3X字节，Tex3DS／C2D为明确API替身；覆盖已有32帧／三个位置和新的动态实例令牌。
- 生产声音检查：4,052项通过，输入三份真实缓存PCM，NDSP为明确替身；覆盖动态绑定、拒绝时命令保留、暂停、实例删除、全局自然结束及BGM队列不变。
- 三个受影响Python套件35项通过（154.808秒）；Windows仅核对349项CTest登记，不视为执行通过。完整新矩阵与真实SDK待验收。

七个受影响模块重新编译，并链接经指纹核验的既有117模块归档；声音测试另编译现有AudioPlayer。这不是完整核心重编译。没有GPU、实际NDSP、听感、正式墓穴、新产物模拟器或真机通过结论。

第一轮核心检查因测试选定Timer尚未超时就访问空实例数组，被UBSan拒绝；第二轮安全断言保留了同一初始化错误。测试现在根据受检原delay／interval越过首次超时并先断言非空。绘制／声音测试各有一次测试命名空间及auto类型推导编译错误。全部原始失败日志保留，原引擎期望没有修改。

详细输入指纹、原始日志及清理记录在 `reports/geyser-instance-presentation`。正式场景生命周期、物理接触与伤害、地图显示和剧情入口仍须继续接入。
