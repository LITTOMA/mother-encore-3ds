# 七种道具的生产资源整合

已把原四种道具与墓穴的 Hamburger、Fries、Antidote 接入正式 Items、描述、仓库、会话和 START 菜单资源。三种新道具沿用稳定号 5／6／7；七处一次性领取分别提供四份汉堡、一份薯条、两份解毒药。场景中的棺材、掉落物与拾取尚未接入正式墓穴，不能据此宣称普通游玩已能取得这些道具。

食物与状态药由独立菜单资源描述效果、消息和声音请求；旧 Items 动作投影继续禁用。正式菜单为 ENCFMN01 v3，会话为资源 v12，存档仍是原 ENCSNAP1 v1。描述资源 v2 增加受检的字面百分号和第二种状态图标，保留原 HP 数值、剂量、昵称与双语格式；仓库资源 v2 支持同种道具的多个领取来源及原排序。旧版读取和冻结二进制仍有独立正向／负向检查，不通过把新版载荷冒充旧版来验证兼容。

原 TargetCharaSelect 的 `menu` 参数是音效节点名称，实际输出总线为 SFX。食用声音按原音源追加到原音频库，稳定号 1801；原 60 条记录、增益、循环设置及 PCM 全部不变，追加后共 61 条。使用与原回执相同的 FFmpeg 7.0。字体通过原工具核对完整字形集合，复用原图集；没有引入新字体。装备目录核对七种定义，只有原装备进入装备候选。

整合中发现棺材／木桶来源记录绑定整个音频清单。审查确认只新增食用音效：65 个实例、两类预制体、规则、原爆破声音以及编码后的资源完全相同，随后仅更新该来源指纹。又实际运行两次原 Godot 引擎，各 282 条观察逐字等于历史两次结果；旧回执保留，新回执位于 `reports/breakables/audio-append-original-1`、`audio-append-original-2`。命名依赖工具仅允许经原生成器验证的 v11 → v12 扩展，并要求命名游戏二进制与实际纹理完全不变。

实际验证保留在 `reports/item-admission`：

- 18 个 Python 模块、213 项检查通过；消费、排序和棺材分别使用两次实际原引擎结果，覆盖 240 例消费、98 组比较／584 份完整库存、每次 282 条棺材观察。
- GCC 9 ASan／UBSan、正常泄漏检查下，八组程序共 1,026,204 项检查通过。其中领取覆盖全部 128 种来源旗标组合及 280 次旧存档往返；仓库覆盖重复排序幂等、所有存取的 UID／剂量保持；11 份坏消费观察和 5 份坏排序观察先验证正向，再逐个以退出 1 拒绝。
- 重新编译七个受影响核心模块，其他实际链接的 34 个归档成员逐个重新计算源码与全部工程头文件依赖并核对。部分测试程序只在其源码和依赖完全相同时复用。这是定向回归，不是完整主机重建。
- 完整资源暂存来源校验通过；当前 Windows 配置实际发现 385 项 CTest，前置输入依赖已登记。配置不等于执行完整 CTest。
