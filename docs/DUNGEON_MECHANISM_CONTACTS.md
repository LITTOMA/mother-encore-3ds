# 机关接触与原版回调

`DungeonMechanismContacts` 把受检机关形状、已有 `FieldAreaContacts` 接触采样和 `DungeonMechanismState` 原版方法连接起来。它从 ENCDMP01 中读取实际拥有者、形状角色、碰撞层及监听状态，不在 C++ 保存地图节点、内容编号或调参表。格式、正式资源、规则身份和存档编码均未改变。

世界调用方仍须提供当前玩家身体或攻击区域与各个受检矩形的几何重叠。其他身体不能作为当前玩家提交；这不是移动求解器或完整物理服务器。拉杆进入调用 `Hit`，踏板进入调用 `PlayerEntered`；停留与离开不调用操作。碰撞匹配保留原版双方 layer/mask 的 OR 关系，攻击区域还需可被监听。暂停、初始化等待、单向和 `can_switch` 均交给已有原版方法消费者处理，进入事件不会因为当时不能操作而排队重试。

开始阶段先在副本上发布上一物理采样并执行整批原版方法，全部成功后提交接触和机关状态；失败保留原状态、事件及待发布接触。结束阶段仅在成功校验当前过滤条件和完整重叠数组后保存新采样。场景 epoch、受检资源实际拥有者、重复开始／结束、错误数量、非布尔重叠及超限碰撞位均明确拒绝。原版形状和几何相交、接触延迟、节点处理时序及动画消费者是不同边界，不能把本模块当作完整墓穴场景。

原版对照使用固定上游的十四个真实机关实例、原脚本／信号和原生物理服务器。玩家代理保留原版八点身体多边形、身体过滤器、球棒胶囊与节点变换；玩家移动／暂停、相机和输入由明确的测试服务提供。两次独立 Godot 3.6.2 运行的 22 组场景、49 个稳定观察结果完全相同，包括：

- 进入、停留、离开再进入；单向踏板成功后不再操作。
- 暂停或尚未完成初始化时进入；原地恢复不会补触发，重新进入才操作。
- 禁止切换时仅在进入时请求原版 `switch` 提示音。
- 双方碰撞层／掩码、攻击区域禁用与不可监听；其他身体进入踏板不操作。

共享核心用这些冻结结果逐项核对五个开关状态、实际操作和声音请求，通过 2932 项 GCC 9.4 ASan+UBSan 检查，保留正常泄漏检查。另有四项 Python 检查核对两次原版结果、来源指纹、现有共享核心玩家轮廓及损坏记录拒绝。容量耗尽回归确认下游失败不消耗待发布进入事件，可交给准备完毕的消费者重试。初次本地脚本因 CRLF 未执行编译；修正调用脚本后，初版夹具因没有提供严格要求的五项旗标而被拒绝。补齐实际全假初态后通过；这些失败记录保留，没有修改原版期望。

本次原版探针只检查稳定接触结果，不宣称精确物理帧、完整场景、可听性、模拟器或真机通过。正式主程序尚未创建该接触服务；墓穴、Pippi 救援及后续原版内容继续待接入。证据在 `reports/dungeon-mechanism-contacts`。三个临时引擎工程的拥有者、绝对路径、文件指纹和进程检查在清理凭据中保留。
