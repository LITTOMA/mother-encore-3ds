# 开发计划

目标是在 Nintendo 3DS 上完成 Mother: Encore 的原生移植：以固定上游为内容来源，电脑自动测试与 3DS 使用同一游戏核心，保留可核对的行为、资源和存档兼容性。电脑测试不构成 PC 游戏版本。当前已实现范围见 [STATUS](STATUS.md)。

默认按 **400×240** 上屏重新适配，图素保持 1:1；320×180 只用于明确选择的原作参考。平台适配不修改官方上游源码。目标包含 Old 3DS / 2DS 与 New 3DS / 2DS，各设备的兼容和性能需要分别实测。

## 1. 完成程序 / 数据分离

已盘点的开局范围已接入独立受检资源，清单见 [CONTENT_MIGRATION](CONTENT_MIGRATION.md)。后续扩展内容继续执行下面的迁移与验收要求，不能把未支持的地图或机制算作完成。

1. 盘点 `runtime/`、`include/`、平台层及转换工具中的真实内容、绑定和调参：文本、地图、角色和遭遇定义、剧情序列、动画与菜单布局、资源路径、来源映射及数值表。区分执行机制、schema 边界与真实游戏数据。
2. 为剩余内容定义独立资源格式、稳定身份、版本和加载校验；不借更名或 `constexpr` 表把内容留在 C++。
3. 从已审查上游与受检 IR 编译资源，替换相应代码消费者。保留原行为、随机数调用顺序、剧情时序和已有存档身份。
4. 为新增解析和版本路径加入缺失、损坏、重复身份、错误来源、未知记录和不兼容版本的负向测试；加载失败不得提交部分会话。
5. 仅在明确手动请求时运行完整主机、GCC / Clang sanitizer 和真实 3DSX / CIA 回归；日常开发不自动跑测试，未验证状态如实记录。

完成标准：完整迁移清单可审查；声明范围的真实内容均通过受检资源加载；没有静默默认或内容常量表；数据变更无需改 C++，未知能力仍明确阻断。包格式、能力集合、规则兼容和存档 schema 独立版本化。

## 2. 补齐开局与场景生命周期

原版 Introduction / Mt. Itoi 到房屋的资源与运行消费者已接入。房屋正门到 Podunk 的跨场景路线、Podunk 全部图层与碰撞已接入（见 [PODUNK_FIELD](PODUNK_FIELD.md)）；下一步是 Podunk 内依赖链与 3DS 实际显示、声音和操作验收。每个受支持场景先建立来源与能力清单，明确继承、实例覆盖、脚本默认值、动态生成、信号与资源依赖。

场景切换需要验证旧场景任务与句柄失效、持久玩家 / 摄像机归属、进入树与 Ready 顺序、触发区域和随机数副作用。切换准备失败应保留旧会话；不可恢复的提交失败必须明确报告。未支持的原版脚本或动作不能被忽略，也不能将未经集成的实验模块计入支持范围。

完成标准：从正常入口完成受支持的开局 → 房屋 → 下一场景，移动、碰撞、对话和旗标与同一固定上游对照；往返切换无旧对象写入或资源泄漏。

## 3. 扩展剧情、战斗和菜单

按真实地图与遭遇依赖扩展，先审查所需原版机制，再编译引用它们的内容。优先形成完整可玩链，不用 M0 fixture 数值或战斗替代原版规则，也不提前实现通用 Godot / GDScript VM。

房屋中的 Minnie 普通仓库已接入原版对话、两栏存取、装备确认及 Record / LOAD，当前只接受帽子和已领取喷雾。帽子和喷雾的原版富文本描述、自由行走的 Pause → Equip 装卸与七项属性预览已接入。实际场景出口已接入：出门接收完整 Podunk 场景（全部图层、碰撞、草丛与剧情触发登记），不裁出伪造的前院替代原图。敌人生成器在野外敌人与战斗链接入前作为明确开发边界，属于记录在案的过渡状态；接入时可见性按 400×240 视口计算并登记为与原版的差异，320×180 参考模式保留原版尺寸用于对照。下一步依次推进 Mick 与狗粮剧情、Podunk NPC、进场随机数重置、音乐区、野外敌人与战斗；保留菜单装饰与音频滤波差异作为明确未完成项。

每个新增切片应覆盖剧情条件、异步人物动作、战斗进入、回合、结果、奖励和返回世界；随后补齐该切片实际使用的物品、技能、状态、队伍和菜单。随机流及调用顺序必须对照，不随意拆分机制与表现的 RNG。

完成标准：相同初始状态、输入与受控随机事件下，关键状态、事件顺序和资源身份与原版一致；取消、失败、死亡、缺资源和存档边界都有明确行为。

## 4. 演出、音频和平台验证

随着受支持内容增加，扩展动画、前景遮挡、战斗背景、音乐与音效；视觉差异按具体效果登记。性能优化须保留已声明的行为和画面精度，近似或时间量化应单独说明。

在真实 Old / New 3DS 上分别测试 3DSX 与 CIA：启动、方向键 / 摇杆 / 触摸、HOME、休眠恢复、退出、SD 故障和存档恢复。测量普通堆、LINEAR、VRAM、音频缓冲、切图峰值与帧时间，并进行重复切换检查。真实交叉构建已经建立，真机验证仍未完成；模拟器只作补充。

完成标准：声明设备和构建配置有独立运行记录；声音、输入、存储与生命周期已验收；性能和内存结论来自实测。

## 5. 上游更新与发行

在独立候选 checkout 审查新上游，保留官方子模块原样。完整 diff 后分别处理内容变化、机制变化、删除与稳定 ID 迁移；不得只刷新 reviewed SHA 或 trace 期望来消除失败。具体步骤见 [UPSTREAM_WORKFLOW](UPSTREAM_WORKFLOW.md)。

发行记录应包含源码与上游提交、工具链、转换器、资源和存档版本、覆盖范围、实际测试、二进制哈希、设备结果及已知限制。核对逐项素材 / 字体 / 库许可并随包保留 notice。声明支持范围内不能含未分类机制；不能承诺尚未实现的自动更新或回滚。

## 每项工作的验收

| 方面 | 要求 |
|---|---|
| 来源 | 固定文件、函数或节点，记录依赖及实际语义审查 |
| 实现 | 内容在独立受检资源；执行机制在共享核心；3DS API 留在平台层 |
| 测试 | 相关正常 / 负向用例及原版对照；按影响运行完整回归 |
| 构建 | 实际主机、sanitizer、交叉构建和打包日志；各层结论独立 |
| 兼容 | 包 / 能力 / 规则 / 存档版本与稳定 ID 的影响明确 |
| 文档 | 更新当前范围、限制和可重现步骤，不以代码量估算完成度 |

贡献流程见 [CONTRIBUTING](../CONTRIBUTING.md) 和 [Git 工作流](GIT_WORKFLOW.md)。
