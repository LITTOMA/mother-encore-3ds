# 房屋移动与交互

开局房屋切片连接了卧室、走廊、楼梯、客厅和已支持的支线路线。具体剧情、战斗与存档范围见 [STATUS](STATUS.md)。

## 来源与数据

房屋资源由固定上游场景、人物配置、门与区域脚本编译生成。路线、传送位置、人物身份、对话条件、阻挡文字和剧情触发均位于外部受检资源中；未知路线或能力明确拒绝，不以通用脚本解释器补齐。

来源清单与参考数据位于 `reports/house-data/`、`reports/house-animation-reference-final/`、`reports/house-profile-reference/` 和 `reports/house-record-presentation/`。

## 运行机制

人物移动使用原版运动与碰撞规则。门切换按源时序完成淡出、移动、朝向更新、接触区域通知与淡入；进入范围、打开门和提交剧情是不同事件。

妹妹房门保留原版条件：向上奔跑且发生新的 body-enter 才解锁，在区域内部才开始奔跑不会补触发。旗标写入、延迟玩家碰撞、下一 idle 的门叶显示和一次性关闭计时按原 callback 顺序处理。门叶位于原始 Below 图层，不能靠额外障碍修补显示。

对话保留源条件、说话动画、文字推进和异步交还控制。Carol、电话和 Dad 的已映射流程见 [CAROL_PHONE_RECORD](CAROL_PHONE_RECORD.md)；Doll 与 Pillow / Minnie 的状态变化分别由对应剧情资源驱动。

## 开发边界与存档

尚未支持的出口在下屏显示开发边界，B 返回先前安全位置。这是开发期恢复行为，不代表原作的门锁或该路线已经实现。房屋正门 `Doors/Podunk` 已有受检路线，进入 Podunk 室外（见 [PODUNK_FIELD](PODUNK_FIELD.md)）；地下室两处出口仍是开发边界。

奖励与剧情旗标通过当前会话和已接入的 Record / LOAD 范围管理；退出不会自动保存。存档恢复需要完整校验与新场景准备成功，未知场景或身份不提交部分状态。

## 验证

共享核心检查覆盖移动、接触区域、门条件、传送、人物动画和对话时序，使用保留的原版参考数据。完整 AnimationTree、其他房屋对象、后续剧情和真机性能仍需独立验收；局部 trace 与测试通过不能代表全游戏行为等价。
