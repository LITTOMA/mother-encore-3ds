# 加载任务进度与精确区域采样

## 加载任务进度

每次加载开始前建立明确任务计划；人物的水平位置表示成功完成的任务比例，各任务等权。它不表示耗时、字节数、任务成本或剩余时间。文件读取 / 校验 callbacks 只在上次确认的位置更新动画，不能将各自分母混合为整体进度。

启动计划贯穿资源准备与标题就绪，避免中途重置。后续标题、命名、New Game、LOAD 与战斗入场各有明确生命周期任务；缓存阶段仍校验或重新绑定 owner。只有最终提交成功后发布右端点，中间比例上限为 0.99；验证失败不能产生 100%。指示器不推进游戏时钟、输入、随机流或内容动画。

受检 right / bottom margins 同时定义对称左边距：400×240 下人物行进 x8 → 361，320×180 参考模式下为 x8 → 281。最近整数像素定位保留原 31×29 帧和 0.8 秒右行循环。共享 `LoadingTaskPlan` 与平台 `LoadingScope` 分别负责任务状态和绘制。

## 精确区域采样

`RegionBackgroundKernel` 使用既有受检图像、调色板和输出偏移，证明支持的常色区域；仅当保守坐标包络完全落入该区域时省略逐点采样。不支持的形状、参数、时间、分配失败或资源上限继续使用精确基线 sampler，不能静默采用近似图像。

区域、斜率与行缓存有界；源图像和 GPU 输出 ownership 不变。浮点构建保持禁止 contraction 的对照约束，不启用 fast-math 或 reassociation。可选 GPU 路径按各自开关与证书检查运行；本页的 CPU 区域测量不能推广到这些路径。

## 局部测量

隔离 ARM 原型针对 REGION32 与 AFFINE32 对照了 1,228,800 个线性像素和 8,388,608 个映射字节。400×240 REGION32 的 mapped CPU 时间为 32.839–37.553 ms，对照 sampler 为 51.844–60.360 ms。

这些是特定原型和 Azahar 配置中的内核测量，不是当前完整游戏 FPS、真机性能或原版 Godot GPU 像素等价证明。后续资源上限、生产接口或 GPU 路径变更须重新验证相应范围，不能直接沿用原型数字。

## 验证要求

保留 host / sanitizer 的像素与失败注入对照，以及真实 ARM 构建。完整帧性能要分别记录准备、采样、编码、上传和 GPU 提交耗时，并测量临时内存与驻留峰值。加载任务位置和完成端点需通过实际入口检查。当前支持范围与硬件限制见 [STATUS](STATUS.md)，构建与测试入口见 [BUILD](BUILD.md) 和 [TESTING](TESTING.md)。
