# Original opening Items menu

The pinned fresh-game inventory contains only an equipped Baseball Cap. The menu now opens, displays its original icon/equipped marker and native-font description, accepts navigation and information-panel toggling, rejects using the equipped cap, and returns to the selected command with B. It does not add a healing item, spend a turn, alter equipment, or consume gameplay RNG when inspected.

Inventory definitions, initial instances, capacity, owner, textures, layout, colors, original Open/Close/cursor tracks and typed sounds are external checked binary content (`data/opening.encitems`, magic `ENCITM01`). The checked 5,576-byte pack uses 11 sections. `InventoryState` is session-owned and is initialized once, while menus borrow it. C++ contains only mechanics and schemas. Current executable item effects are a later stage tied to authentic acquisition; a future selectable item outside this bounded menu must not silently become a heal or no-op.

The source menu is two columns/five visible rows. It keeps original 320×180 coordinates and uses external anchors for the default 400×240 canvas. Native Godot3.6.2 verified the description's two lines, panel dimensions, cursor position and info offset. Source `ui_scope` is mapped to 3DS L, reflected by an original-font L glyph. Both Circle Pad and D-pad navigate the battle/Items menus. Held navigation respects the existing source repeat delay; submenu Back preserves selection, while a new round resets the command menu.

Four original menu cues are in the audio bank. The original restricted WAV is 96kHz; its explicit asset recipe requests 48kHz PCM for the supported stream format. The conversion and original source rate are recorded, and pitch/duration are preserved by resampling. This is not Godot decoder bit-equivalence or a hardware audibility claim. The cloud environment still lacks the DSP component.

Evidence: reports/items-menu-source/ contains native font/layout output, 13 asset/provenance tests, 10 compiler tests and the checked loader's sanitizer cases. `items_menu_tests` verifies original initial inventory, repeated inspection/restricted confirmation/cancellation, retained info setting, original animation endpoints and unchanged turn/HP/RNG. Historical Azahar ARM text telemetry confirmed menu input and the complete Lamp→Doll battle route without capturing images. It does not establish visual framebuffer equivalence.

## Native input adaptation

The platform polls directions once per displayed frame. The external `content/platform-input.json` is compiled as `InputRepeat` in the checked Items resource:350ms initial delay,100ms subsequent interval. Each press emits one movement; release/direction change resets its delay. Menu-context changes suppress held input until neutral, and a stalled frame emits at most one repeat. D-pad and Circle Pad are OR-normalized before opposite directions cancel; inventory diagonals prioritize vertical. This is the user-requested native adapter, distinct from the retained source50ms cursor gate. Pre-gated pulses bypass that inner gate so rapid separate presses are not lost. A/B remain hardware press edges.
