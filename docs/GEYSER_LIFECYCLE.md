# 墓穴喷口实例生命周期

当前候选把原版37个喷口 Timer 的请求交给受检实例工厂，保留待加入、Ready、播放、延后方法及排队销毁的不同阶段。它尚未创建正式墓穴，也没有把物理接触、角色受伤、GPU或NDSP接入游戏入口，不能据此增加已支持的可玩范围。

## 来源与资源

固定上游为 `7d9246600fffe518408f5830d4848635019005a3`。`content/catacombs-geyser-lifecycle.json` 检查原 `Poison Geyser Hole.gd` 的 preload 与 `_on_Timer_timeout`，从真实方法提取工厂场景和 `get_node(...).call_deferred("add_child", ...)` 的父节点。绑定、地图身份与原位置来自资源，C++不包含这些路径或游戏调参。

独立 `ENCGLF01` format1 / capability1 为8,140字节，包含字符串池、32字节绑定记录，以及不变的6,360字节 `ENCPSN01` 和1,552字节 `ENCGYS01`。嵌套格式独立校验，父子来源与场景身份必须相符。此候选没有修改正式资源目录、规则兼容或存档格式。

加载检查格式、能力、固定上游、CRC、目录跨度、对齐空洞、字符串所有权与路径、保留字段及嵌套来源。加载失败不提交部分所有者。运行期检查场景代次、原 Timer 所有者、递增实例票据、一次性的原偏移和容量；容量或信号分派失败同时保留原计时器队列与注册表。

## 原版执行顺序

实际Godot3.6.2使用完整原喷泉脚本、场景、Timer、PackedScene、自动AnimationPlayer、MessageQueue和queue_free。观察器仅提供明确的Player暂停、UI及声音命令服务；源图片／MP3只放在私有临时工程，不进入报告或发布资源。原场景的空间位置全部离屏，本次原版记录不推断可见性或全局声音所有者。

两种节点顺序各实际执行两次，每次720帧、97个真实实例：

| 顺序 | 两次原结果SHA256 | 报告 |
|---|---|---|
| 控制场景Objects在Timer之前 | `a0cc90773c3edccb32b4fe3a0c509cffdadce0da7df9a5e22c79836e623e6844` | `reports/geyser-lifecycle/native1`、`native2` |
| 原地图选定顺序，Timer在Objects之前 | `9a376423e27d89b975b476b27350e2e0f133a9f044d334cb805db5da2b4ff405` | `reports/geyser-lifecycle/map-native1`、`map-native2` |

第二种场景只保留原地图相关节点的相对树顺序，没有假称加载完整地图。原地图全部喷口在Objects之前，故不能用第一组替代原地图顺序的验收。工厂注册先转交真实PackedScene.instance，再记录完成的分配；继承包装器让原Ready自动执行，不重复调用。Timer包装器明确先调用原方法，再记录观察，不依赖额外信号连接的先后。

官方Godot提交 `3cd3caab6779a7f3ec3bbeb9f200db50c735cfc8` 的 `scene_tree.cpp`、`node.cpp`、`node.h` 已逐个验证Git blob与SHA256，原文件及MIT许可在 `reports/geyser-lifecycle/engine-source`。内部动画、Timer和脚本_process不是同一个阶段；遍历中的暂停会影响尚未执行节点。执行器分别提供单个Timer、动画组和UI阶段，由已审查调用者保持树顺序，不把稍后发生的暂停倒灌到已经执行的动画。

新实例在延后加入前接不到早先的Player／树暂停通知。原Ready播放并连接信号，没有自行同步过去的暂停状态，因此工厂也不补发通知。原脚本的延后方法在加入后处理；声音命令按实际阶段汇入全局有序传输，避免先按实例积攒再重排。命令与延后方法交付前不能销毁实例，已销毁票据或旧场景代次不能再写入；外部命名声音保持自己的生命周期。

## 验证与失败记录

`geyser-lifecycle-host-1` 首次比较在第228帧动画时间失败。原因是测试驱动把后续Timer触发的树暂停用于较早执行的动画阶段。原引擎期望没有改变；拆分执行阶段后，第二组主机检查通过，随后加入独立原地图顺序与负向测试。

最新 `geyser-lifecycle-host-3` 实际通过2,946,170项GCC ASan＋UBSan检查，开启正常泄漏检查。它比较两种原版顺序的全部Timer、实例位置／属性、声音命令与销毁，并检查8,140种截断、版本／能力／目录／来源错误、暂停通知时机、票据重放、容量回滚、失效引用及命令未交付时的销毁拒绝。三个受影响模块重新编译，链接受指纹校验的不变117模块核心归档；这不是完整核心重编译。

原Poison计时批处理回归另通过117,974项正常泄漏消毒器检查，旧720帧、99次回调和102个延后位置不变。控制观察器共享验证逻辑的重构没有改变生成的Godot输入；重新运行的两次结果仍与原4／5记录逐字一致。历史生产器、早期失败和原4／5记录均保留，压缩记录附有解压后指纹，不以新期望替换旧失败。

13项Python正常／负向检查通过（104.391秒），覆盖来源变更、两组原记录、未知字段／操作／类型、资源版本和夹具所有权。Windows带Debug配置仅发现348项CTest，未执行完整测试；无配置的初次发现0项保留为登记诊断。完整新提交、真实SDK和新产物模拟器尚未验收。所有原版/主机日志都在 `reports/geyser-lifecycle`。上述检查不验证物理采样、正式角色接触、NDSP、GPU、完整墓穴或真机。

已实际核验并清理三批共110,279,290字节临时项目、重复原结果和被替代失败测试程序；保留生成源码、原始日志、受检记录、当前夹具与最新程序。清理审计与完成记录分开保存。
